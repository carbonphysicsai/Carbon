## Local commands

Use the existing private operator, registered distinct miner, credential and
image files. No command here registers an identity or sends a chain transaction.
Build the separate analysis image from the accepted parent using
`python -m carbon.development_session.research_image --help`; it uses only local
pinned image/dependency material. Its exact manifest is an execution input.

The execution entry point is:

```bash
python -m carbon.development_session.research_campaign run \
  --root "$CAMPAIGN_ROOT" --accepted-revision "$ACCEPTED_REVISION" \
  --image-manifest "$TRUSTED_IMAGE_MANIFEST" \
  --analysis-image-manifest "$ANALYSIS_IMAGE_MANIFEST" \
  --operator-config "$OPERATOR_CONFIG" --api-key-file "$API_KEY_FILE" \
  --miner-public "$MINER_PUBLIC_FILE" \
  --miner-password-file "$MINER_PASSWORD_FILE" \
  --quarantine-journal "$QUARANTINE_JOURNAL"
```

The run requires the exact clean accepted commit, verified as an ancestor of
fetched main. Paths are private operator inputs, never model arguments. Existing
credentials must be owner-only, in a private parent directory. The first run
prints the actual campaign directory and a ready-to-paste status command:

```bash
python -m carbon.development_session.research_campaign status --root "$CAMPAIGN_ROOT"
python -m carbon.development_session.research_campaign report --root "$CAMPAIGN_ROOT"
```

Open `research-report.html` in that private directory. `research-report.json`,
per-epoch outcomes, full curves, practice diagnostics, worker snapshots and signed
source handoffs remain alongside it. The report separates single-construction
adaptive practice from the independently reconstructed final comparison.

For an interrupted process use `resume` with the same arguments. It reuses exact
completed observations; an unresolved provider/tool/final dispatch stops for
read-only journal reconciliation. It never treats uncertain consumption as zero
or automatically repeats reconstruction. A completed campaign stays completed.
