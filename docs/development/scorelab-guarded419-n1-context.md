# Prospective guarded419 score-value context

The guarded controller changes the reference/construction context. The original
N1 registration, tasks, TRAIN390, model fits and commitments remain original
4.2-V artifacts. They cannot be renamed into the guarded experiment.

`guarded419_context.load(expected_sha256=...)` authenticates a new committed
registration and original approved provenance, returning a nominal immutable
context. Caller dictionaries, job aliases and arbitrary module names do not
select a producer. `owner_v3` accepts the context explicitly for task validation,
whole-question reference masks and the existing per-band deadzone judge.
Default calls retain the original identities and algebra.

The new registration preserves every approved N1 numeric constant and unit.
Original TRAIN standard deviations are EXTERNAL scoring constants only, not
new physical labels or new model training normalizers. The new model fits its
normalizers from newly admitted construction rows only. The buyer limit stays
4.2 V even though the controller commands 4.19 V.

Each band task and the indexed map receive prospective context-bound digests.
Commitments must be made for those new tasks; old commitments fail. All five
bands, including zero-weight bands, remain mandatory. Same decision algebra,
common reference masks, LEG-only scoring/selection and VALUE-only judging apply.

## Integration dependencies

Packets owns the separate guarded419 EVAL producer. T9/TRAIN evidence is not an
EVAL certificate. The adapter must authenticate complete compatible CAL,
registered reference sources/observers, all offered EVAL rungs and enclosures,
and the exact new task context. A missing API or receipt refuses the run.

The existing CLI is frozen in PR1394. Root must merge/reconcile that dependency
before its context integration is edited here. Dispatch to the new producer is
closed and static. A missing module or CAL interface refuses the run; it never
falls back to the original producer. Each new receipt carries the exact
diagnostic context, new job and EVAL observer alongside its dynamic source,
method, CAL and bank bindings. Source availability supplies no accepted bank.

`guarded419_context.acquisition_plan(context)` reads the pinned original
input-only plan and replaces only its job identity. Context-aware
`owner_v3.acquisition_inputs` and `population_tasks` preserve the 60 physical
tuples, original P law and deterministic 64 draws/32 LEG/32 VALUE roles. They
mint fresh task, job, observer and bank identities. No old label, prediction
or commitment is transferred by these input-only functions.

Root owns all project tests and execution. Synthetic parity/refusal fixtures
exercise the context/decision seam, not CAL adequacy or model quality. No
historical v2 reconstruction, score adoption, hidden/final holdout, scientific
qualification, reward or LIVE effect follows.
