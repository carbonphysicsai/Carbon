# First owner block: T-07 only

Controlling direction: OWNER-LAUNCHPAD-E2E-SUITE-01 D3/R1/R2. Two90-minute
blocks a week are owner-authorized from the week of2026-10-15. Root selects
the actual block time; the lane finalizes this agenda the day before it.
This document does not claim that a calendar slot, release or TEST lease exists.

## Bind before the block

| Required identity | Actual source, no invented replacement |
|---|---|
| Miner machine | carbon-fresh; selected existing miner state and accepted release/profile/image identities |
| Miner key | Owner's actual registered miner public principal and existing signer/socket label, verified independently; no publisher bootstrap substitution, private key read or automated TTY confirmation |
| Target machine | Existing owner-authorized validator route; Root verifies actual tunnel target and receiver independently, rather than copying a configured value as proof |
| Target keys | Actual pinned receiver public identity; owner's existing miner signer for the frozen commitment; no new key/account setup in this block |
| Subject | Explicit registered base contract digest; no combined086/ad15 or level/dev-ladder substitute |
| Prerequisites | Mandatory historical backfill, accepted commit-operation release/image/runtime, pre-existing compute/inference setup, exact route/client and Root-issued TEST scope/bounds |
| Recorder | One named lane recorder with the existing cells/FINDINGS files ready before the block; private raw output stays with Root |

Unresolved concrete prerequisites are findings to resolve before dispatch.
There is no request for another owner GO on the already answered decisions.

## In-block order

1. **Tunnel:** owner verifies the existing authorized target path and independent
   receiver. Do not expand exposure or configure another machine during T07.
2. **Review:** same existing Launchpad door, current own profile and base target.
3. **Launch:** existing `carbon_launch`, exact base subject and frozen request key.
4. **Practice:** one existing approved bounded base recipe via `carbon_practice`;
   keep the returned task and unchanged retry key. No compute/inference/snippet
   exercises are added to this block.
5. **Freeze:** `carbon_freeze_candidate`, same practiced recipe, recorded digest.
6. **Commit:** `carbon_commit`; actual owner confirms in the signer's TTY. Record
   finality/receipt, reconcile an unknown result rather than resend.
7. **Submit:** `carbon_submit`, commitment first and independently pinned receiver;
   record durable admission separately from a successful HTTP response.
8. **Verdict:** existing own `carbon_observe`/`carbon_campaign_view`; record actual
   terminal/refusal/infrastructure/pending outcome without hidden fields.

Write F05-F12 cells only as their actual predicates are observed DURING the block.
If a step fails or cannot proceed, record its exact finding, closed outcome and
owning ticket then stop retries. A finding is the block output. No failed or
blocked cell shows tested, and no unrun downstream cell becomes PASS.

F15 two-target admit/refuse coverage, additional compute/inference/client options,
and deferred levels are later coverage. The first block is not widened to fit
them. A successful first F12 starts the following-week dev-ladder sequence; it
does not declare the whole Launchpad suite complete.
