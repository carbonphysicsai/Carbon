# Battery design search: priced choices for the owner

**Ticket:** GRAPHITE-ADMISSION-01 slice C (handoff §11). PB-ADV's K beyond
EV4, the design grid resolution, the Mode X condition grid and the PB-INV and
PB-ADV acceptance policies are the owner's. This page prices concrete choices
and chooses none of them. The tables are generated by
`carbon.battery.value.design_search_pricing.render()`, and a test keeps this
page equal to them.

**Basis.** EV1 measured about 65 s per pinned-PyBaMM reference solve with 4
workers on the lead host's CPU (`docs/development/DESIGN_OPTIMIZER_SCOPE.md`
§2). Model predictions are counted, not timed. Solve time on the approved
reference hardware (`runpod-cpu5c-16vcpu`) has not been benchmarked, so no
time there is claimed. Money appears only from an owner-supplied rate, and is
HUMAN_INPUT otherwise. The panel size of 5 is EV4's, as an example.

**Development material.** A condition grid that includes any EV4-protected
condition cannot be a development grid: `search_commitment` refuses each one.
EV4's own 8 x 4 model grid is entirely protected, and the dense 15 x 10 grid
contains all 32 of its points.

## What the owner decides

- K for PB-ADV beyond EV4's 50.
- The design grid resolution, and the Mode X condition grid. A development
  grid must avoid EV4's protected conditions.
- The PB-INV and PB-ADV acceptance policies (`DESIGN_OPTIMIZER_SCOPE.md` §4).
  The pilot reports and never passes or fails a model.
- Before any paid run: a benchmark of reference solve time on the reference
  hardware, and the rate.
