# Motor preparation: recorded automation rehearsal

ONBOARDING-AUTOMATION-REHEARSAL-01. Public DEVELOPMENT preparation, not a
scientific or customer result. Candidate tool heads are recorded exactly;
none is copied into a stacked PR. Status records use PREPARED, never an
accepted stage exit. No physics solves, hidden material, cloud action or spend.

The matched workload is **four bound motor packet clauses, three motor law
anchors, and the existing incomplete motor panel draft**. The control invokes
the same checkers separately per clause; the batch invokes each checker once.
Compare the actual rows/panel output for exact equality. This is a command-
consolidation benchmark, **not** a historical manual-review workflow or
strongest-cheap-method V4 comparison. Source/manifest preparation effort,
unbound fields, reference verification, TRAIN and actual tested onboarding are
outside this narrow timing comparison. It is one unblinded local trial; order,
cache and process startup can affect the observed ratio.

`report.json` records raw phase timings, invocation counts, equal-output
checks, exact tool heads and recorded TOOL-only process events. The motor
panel remains blocked for missing physical seed/pins/inventory. Packet/law
checklists retain unbound fields. No incomplete preparation becomes readiness.

The replayed ONBOARDING-METRICS motor view retains the historical source/API
capture identity. New recorded events add tool clocks only. Human person-hours
and actual human labour speed-up remain **NOT_DEMONSTRATED**: no human active
baseline was recorded. Agent time is not human labour, and subprocess wall
time is neither. The status timer can measure future matched human review
blocks; it cannot reconstruct the earlier battery baseline.

Reproduction requires explicit local worktrees at the exact tool heads shown
in the report, Python 3.11, public source artifacts and full Git metadata:

```text
python scripts/dev/onboarding/automation_rehearsal.py --packet-root <1123-worktree> --law-root <1130-worktree> --panel-root <1125-worktree> --timer-root <1127-worktree>
```

This is an execution producing **new**, append-only event records and a new
timing report, not an idempotent replay of clock observations. It refuses a
pre-existing report rather than overwriting history. Tests validate retained
record structure and equal-output bases; they do not rerun candidate tools or
claim that variable timings must improve. Canonical CI applies to this PR,
not a scientific endorsement of candidate-tool outputs. Hub retired.
