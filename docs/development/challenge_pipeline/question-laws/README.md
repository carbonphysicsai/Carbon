## 2. What is one question?

A question is **one precommitted design decision**: a pinned physical
context, a complete mandatory service panel, a finite action bank, a buyer
requirement vector, an objective/tie rule, and immutable observer/reference/
optimizer identities. The answer is a verified best-in-bank action,
`NONE_FEASIBLE`, or `UNRESOLVED`. Multiple conditions, curve samples,
optimizer probes, model arms or seeds of this same brief are not independent
questions. A finite-bank winner is not a global physical optimum.

Separate three levels:

- **Outer P_job:** synthetic population of buyer questions. Recommended first
  alternatives: uniform over the explicitly listed supported contexts and
  either Cartesian requirement grids or the continuous intervals in §3a.
  The owner selects the alternative before use. This is a synthetic law,
  not a measured fleet,
  factory or customer frequency. Context count is one complete panel except
  f02's explicitly enumerated 24 contexts.
- **Outer Q_job:** diagnostic sampling. Recommendation: `0.5 P_job + 0.5 B`,
  where B is uniform on eligible near-limit question cells defined by a
  prospective, quantity-specific boundary-distance rule. Record the bank,
  reference intervals, classification, support and normalizer. If B is empty,
  use P_job and report that enrichment is unavailable; never manufacture a
  boundary. This is not a grant to inspect protected material in research.
- **Outer w_job:** recommendation for a *population-mean diagnostic* is
  `P_job/Q_job`; keep raw near-limit results alongside it. Test Lead must
  adopt any score use. No population estimate is identifiable where Q has
  zero mass on positive-P questions. Boundary/stress results do not silently
  replace the population estimand.

The **inner panel** defines robust feasibility: every mandatory condition
must pass before ranking. Its P_condition/Q_condition/w_condition, if used,
are distinct from outer masses. Averaging temperatures, plating, cogging,
resonant peaks or mandatory tolerance points cannot erase one breach.
Equal outer mass does not authorize equal inner weighting or prove power.

In the minimal first laws below, service-context P is deliberately a point
mass on the complete supported panel for seven families; f02 varies its
24 already-defined contexts. This is an explicit service-axis law, not a
claim that one panel spans a real deployment. **HUMAN_INPUT recommendations
for later within-bank service variation**: Battery conditioned/warm session
profiles using already-covered ambient rows; Cooling nominal-uniform versus
hotspot versus complete cell panels; f06 covered wavelength subsets with
all tolerance vectors retained; f08/f13 sub-bands only when the original
resolved curve supports their exact peaks/interval quantiles; f17 single
declared service flows versus the complete flow panel, retaining diffusivity
coverage. Such a question asks a different buyer job, not a cheaper substitute
for the original robust brief. Freeze each panel/observer identity and revise
R/P/Q/w before counting it; these extensions are **not included** in the
minimal grid counts. Motor currently has only the declared static command
scope: new temperature, speed, duty or 3D service variation needs new truth,
not invented supported axes. Torque demand variation is the cheap current
lever, with revised command/geometry adequacy still unresolved.

Recommendation: freeze a prospective law manifest with law version/digest,
physical scope, condition/panel identities and physical parameters, actions,
requirement support/dependence, normalized P/Q, intended estimand/w,
near-limit selection policy, uncertainty/refinement, full truth coverage,
optimizer query budget, ties, exposure linkage, clustering and disclosure.
Invalid geometry is refused, reference/infrastructure failure remains typed,
and missing coverage is unresolved. All manifest values remain HUMAN_INPUT.

P context: one simulated cell, initial SOC 0.10, complete 30-cycle programme
at 5/15/25/35/40 °C. Warm 25/35 °C cases carry session-start 10–80% time;
all applicable episodes carry thermal/plating/voltage/capacity constraints.
Propose time ceilings **25/30/35/40 min**, whole-programme temperature
**42.5/45 °C**, and Q30/Q1 floor **0.99/0.995**: **16** raw questions.
Faster targets matter to turnaround; tighter thermal/capacity requirements
express a buyer's headroom and repeat-use concern. Do not loosen the 0 V
model plating floor or 4.2 V bound. Whole-programme discharge peaks remain
visible; no answer to the separate discharge-scope decision is invented.

Q enriches session-time, thermal and model plating band edges, with the
active constraint identified. w follows §2, not a priced safety trade.
Objective: minimum worst warm session minutes; capacity loss secondary;
frozen bank order. A proposed 100-protocol bank gives 500 programme solves

geometry. An operating command is not a free service-context change that
lets a design escape its required precision/peak roles. Define command
selection/aggregation prospectively under #758/#759; a two-second thermal

Peak absolute ripple uses twice that cap; the same fraction cap applies to
peak. This dependence is part of P, not two independent axes: **243** raw
questions. Mean torque buys load capability; fraction/absolute ripple and
cogging buy precise low-load motion. Preserve the original 6/12 N·m,
5%, 0.30/0.60 N·m and 0.05 N·m anchor, rather than declaring an easier
question the robot-joint success.

### Expected winner diversity under either alternative

For a fixed eligible bank, let p_a be the P mass of question regions whose
**resolved** best pick is action a, using the frozen objective/tie rule.
Compute those masses from bank truth: grid enumeration for the baseline;
partition the continuous box at each action's reference/band boundaries and
integrate each answer region's mass, or use a precommitted offline numerical
integration with reported error. No new solves are needed for already
settled quantities. Report NONE_FEASIBLE and UNRESOLVED masses separately;
they are not winners and do not count as distinct good picks.

For k independent draws with replacement from that fixed law/bank:

`expected distinct resolved winners = sum_a [1 - (1 - p_a)^k]`.

For draws under Q, replace p_a with q_a and report both expectations.
Importance weighting does **not** change how many winners were observed.
Do not assume winners have equal mass. Repeated picks can dominate even a
continuous law. This expectation is bounded by min(k, number of eligible
winning bank actions), not by the old grid size. Distinct verdict signatures

### Exposure-limited capacity

Current [`BankLedger.draw_window`](../../../../carbon/challenge_validator/bank.py)
stores a window's selection once and increments each selected case once.
Idempotent replay/model arms of that stored window do not increment again.
A different window drawing the same case increments again, **including a
window asking different requirements of its unchanged truth**. Cases retire
at their separately approved E or sooner if disclosed/inferable. No threshold,
seed, law version or task ID resets underlying-case exposure. #760 publishes
retired cases only after every drawing window has ended and selection is
journaled; public TRAIN cases never return to hidden use. Unretired truths,
tuning/confirmation/study material and EV5 are not public training inputs.

**HUMAN_INPUT recommendation:** start with one question per underlying window
draw. If question j depends on case set U_j and case i has residual capacity
`e_i = max(0, E_i - exposures_i)`, usable *distinct* questions are bounded by
the largest admissible subset S satisfying `sum(j in S: i in U_j) <= e_i` for
every case, additionally bounded by the relevant distinct-question/answer
capacity. For one unchanged complete bank shared by all questions this gives
`usable distinct grid question draws <= min(R, min_i e_i)` and
`answer-diverse draws <= min(D_answer, min_i e_i)` when requiring different
answers. A batch may repeat an answer, but is not independent evidence merely
because it has many threshold vectors.
For continuous requirements, the raw-vector R ceiling disappears, but
`usable draws <= min_i e_i` and the finite answer-capacity bound remain.
Continuous decimals do not supply fresh exposure.

Illustration only: an entirely synthetic bank with five distinct answers and
residual E=2 supports at most two one-question draws, not five fresh hidden
uses. A larger approved question bundle per window would change this bound
and leakage; it is a separate HUMAN_INPUT decision, not implemented here.
Do not change the current ledger unit or mint duplicate case IDs. A shared
physical-support/outer-question linkage and any bundle cap require explicit
producer integration, since existing BankSource banks individual cases.
Different contexts can use disjoint case sets, but must actually be covered;
the simple bound is per shared support, not a universal bank lifetime.
