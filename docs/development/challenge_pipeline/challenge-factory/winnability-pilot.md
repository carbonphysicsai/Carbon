# Early winnability pilot — PROPOSED, not a dispatch grant

The owner-added PKT-08 filter asks whether Carbon can learn a **useful buyer
decision**, beat the strongest cheap incumbent, and support competition. It
precedes expensive full onboarding when possible. Existing public preparation
may be reused. No pilot, solver, fitting or model run occurred in this ticket.
All numerical caps below are **PROPOSED ASSUMPTION**; all pass/park scientific
and buyer thresholds remain **HUMAN_INPUT**.

## Inputs and preflight

One unchanged buyer job, two independent workflow sources (or explicit source
gap), approved safety limits and buyer-unit utility/regret; exact geometry/action
grammar and service envelope; independent P (requests), Q (diagnostic enrichment)
and w (buyer/evidence weights); public rights-cleared TRAIN and grouped held-out
design/condition panel; exact solver/image/deck/material/observer pins and
applicable code verification, convergence, conservation and uncertainty.

Matched separate non-hidden draws or retired published cases only. No protected
EVAL/STRESS/quiz/tuning, hidden bank, EV5, journal or AX42 data. Neither training
nor hyperparameter selection may inspect pilot decision labels. Continuous
requirement draws can reuse outputs but don't create independent solved cases
or renew exposure. Split by physical action/geometry and independent condition
cluster, not randomly by correlated curve point or threshold duplicate.
Report whether this pilot panel was previously used for development.

Insufficient sources/rights → BLOCKED_INPUT. Unsupported law, failed solver or
observer, unresolved reference uncertainty → BLOCKED_REFERENCE/INDETERMINATE.
Do not count them as model error or failure. A missing native image cannot be
cured by a fixture. Reuse evidence only with exact applicability/version checks.

## Outputs: three independent questions

**(a) Learnable.** Pointwise unit-bearing error/curve extrema; decision agreement,
false-feasible and missed-feasible outcomes; verified regret; abstention and
resolved coverage per stratum, including boundary cases. Use reference intervals
to route close calls to refinement or UNRESOLVED. Show whether the MLP meets
buyer-useful accuracy and safe decision coverage, not just low average loss.

**(b) Surrogate advantage.** Paired cheap/MLP/solver verified buyer-unit outcomes
per independent question cluster at matched budgets. Report full cost/time to
an admissible decision, absolute and relative gains, bootstrap/paired uncertainty
using the existing equal-budget route, and cheap-baseline choices. A gain due
only to making an unsafe choice is not value. Charge dataset acquisition,
fitting, queries and retained verification, with M = 1/10/100 served-decision
amortisation as **ASSUMPTION** sensitivity, not demonstrated market volume.
Also check end-to-end latency; raw inference speed is not sufficient.

**(c) Competitive headroom.** Gap from the verified MLP baseline to the best
resolved pilot-bank action/bound, in buyer units and across strata/questions.
Show at least alternative actionable regions and reference-resolution limits.
If every reasonable method ties, it may still be a useful ordinary customer
tool but not a valuable miner competition. Don't add artificial variables or
widen a safety boundary to create headroom. A tiny toy menu needs an honest
cache comparison; a large/continuous space is only an advantage hypothesis.

Retain NONE_FEASIBLE draws without redraws. Declare it only for the registered
menu when every eligible action has a resolved mandatory failure (or a valid
independent infeasibility proof). Any unresolved potentially feasible action
prevents that conclusion. Report feasible/none-feasible/unresolved mix, distinct
best picks and equivalent picks, including per-band battery choices. Question
count is not action count. Counts toward contested boundaries use the Test
Lead's **two-refinement-band working rule**, not widened bands or an overall
20–80% pass-rate gate; production/acceptance values remain HUMAN_INPUT.

## Cheap bound, before deciding to build a bank

Proposed two-step **free CPU only** plan for a later authorized ticket:

1. Reuse valid public solves first. Read-only audit and fit/query harness: one
   process, ≤4 CPU threads, peak ≤8 GiB, ≤2 wall-hours and **≤4 aggregate CPU-h**
   (measured sum, not four cores times elapsed by assumption). No GPU, paid host
   or automatic solver invocation. Proposed 3 MLP seeds share this cap.
2. If reference data is inadequate, propose ≤12 new complete cases including
   every excitation/frequency/condition, with **≤8 aggregate CPU-h**, ≤4 wall-h,
   ≤8 GiB and one process at a time. A single-case probe is the first of those
   12; stop it at the remaining cap or declared watchdog. Its measured cost
   determines whether any further cases fit. Cap is not a promise that 12 fit.

Proposed total: **≤12 CPU-h / ≤6 wall-h / ≤8 GiB / ≤12 complete cases**, with
the overhead and reference portions separately enforced, zero paid spend and
no retries by default. Setup/meshing/extraction/children/failures count. No
per-frequency loophole or allocation outside this ledger. Changed pins require
re-verification counted in the cap. Heavy jobs that cannot fit stop with a
priced proposal; no cap expansion or borrowed family grant. For an f13 curve,
every frequency × excitation launch is additionally enumerated. These caps
require owner approval and an implemented/enforced runner; this document grants
neither. Existing authorized caps are not transferred.

A small triage can rule out an obvious cheap-map tie, but cannot prove tails,
competition power or commercial demand. Too few independent questions for a
meaningful interval produces INDETERMINATE. Do not treat three seeds, multiple
thresholds on one bank or correlated points as the missing sample size.
