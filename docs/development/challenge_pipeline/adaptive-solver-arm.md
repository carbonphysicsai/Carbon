# Prospective adaptive competitors for equal-budget design search

**ADAPTIVE-SOLVER-ARM-01 · DEVELOPMENT · IMPLEMENTED/TOY-TESTED · NOT SCIENTIFICALLY QUALIFIED.** This extends [the equal-budget replay](equal-budget-design.md) with two prospective competitors and keeps its fixed-order historical report distinct. The incumbent recipes and fairness requirements come from [research's EQUAL-BUDGET-REALISM-01 specification](../../../Business/research/equal-budget-realism/SPECIFICATION.md). No Challenge reference solver is run by this code.

## Inputs and custody

`python -m carbon.design_search.adaptive_arms PANEL.json --budget-registration REGISTRATION.json --confidence 0.95 --bootstrap-replicates 1000 --seed 7` prints **aggregate development results only**. `PANEL.json` is a digest-bound `carbon.design-search.adaptive-competitors.v1` object containing:

- An unchanged, sealed `equal-budget-panel.v1`, including the registered three-tier budget ladder, committed Carbon model screen ranks, full-panel reference verdicts and costs.
- A sealed `adaptive-policy.v1`: Challenge, separate calibration source digest, independently held pre-experiment registration receipt digest, direct and surrogate policy configurations, and model cache-access charge. The producer must verify that the independent receipt predates held-out execution. A self-declared timestamp or digest alone cannot establish that chronology.
- One action record per base job: typed canonical lattice, branch, every candidate's coordinates and signed mandatory margins, registered starts, exact-condition public development cache, shared cache acquisition cost, warm-start provenance and ordered solver attempts. The `condition_panel_digest` binds the full buyer question and complete condition panel. Cache entries must match both the current objective/reference and all mandatory margins exactly; the cache source must have a different source digest, matching condition/decision identities and `PUBLIC_DEVELOPMENT` rights. A cold-start job uses an empty cache and null cache source.

The code accepts only the four Challenges in #1047, uses its `BudgetLedger` for **all three arms**, and refuses a base budget ladder or cost-plan identity that differs from the prospective registration. In a real evidence run the Test Lead or producer must register numeric policy settings on separate calibration jobs, establish the pre-experiment receipt independently, and provide measured or explicitly assumption-labelled complete workflow costs. The toy test settings are not adopted values.

## Policies and cost boundary

**Adaptive solver alone.** For f02's current nine-action menu the policy enumerates every finite option in registered lattice order and uses every lawful exact cache hit. For other Challenges it tries registered warm starts, searches nearest untried actions in the current feasible branch, and opens a deterministic farthest-point challenger after registered stagnation. Restarts and stopping are fixed by the sealed policy, not selected after seeing a held-out winner. The policy can react to previously settled outcomes; it cannot inspect an unqueried objective or hard margin. There is no claim that this generic lattice policy is automatically the strongest available industrial optimizer. Challenge-specific direct methods and valid gradients may be registered as separate policies after development calibration, with gradient costs included.

**Ordinary industry surrogate.** A separately registered cold start, initial design and branch-specific radial-basis response surface screens remaining actions. It fits the buyer objective and **each mandatory signed margin in its own unit**, not a single soft feasibility score. Exact prior lookup is allowed under the same source/rights/condition checks. Every selected proposal receives a complete reference panel; a surrogate prediction alone never makes it a verified winner. Motor curves require registered mandatory observables such as torque/ripple/cogging margins; a mean-torque-only proxy is not a suitable panel. Battery v3 keeps all five ambient bands and any-band hard failure. For a future continuous action grammar, a new registered policy is required; this version chooses only from the sealed lattice.

**Carbon model screen then verify.** The existing #998 committed rank and full screening cost are replayed under the same #1047 cap and same common exact cache. This is the Carbon arm for paired comparison, not a reference authority.

Each arm checks the common exact cache first, paying acquisition and each lookup; a fully cached bank needs no optimizer startup. For uncached actions it pays its own startup/screening, all proposal scans, surrogate refits, and every ordered failed/refinement/final solver attempt. Failed infra, failed reference, invalid geometry and refinement attempts have separate trace kinds. The sum of per-attempt wall and core costs and planning bounds must match the sealed base candidate's whole-panel values. The ledger preflights a **complete** panel, including every planned attempt, before the first attempt. If it cannot fit in evaluation count, wall time or core time, the arm stops without claiming that candidate. Warm starts are permitted only from the common exact-condition prior and their actual cost belongs in the attempt record. `FAILED_INFRA` and `REFERENCE_UNRESOLVED` are typed unresolved causes and are never counted as a bad model decision. `INVALID_GEOMETRY` is a separate candidate-caused infeasible outcome with unavailable margins; its attempted query is still charged.

## Outputs and limits

The default report gives, at half/base/double registered budgets, each arm's feasible fraction, conditional best **solver-verified** buyer-unit value, attempts, wall/core spend, and paired Carbon-versus-each-competitor value differences and win fractions. A finite f02 direct run says `EXHAUSTIVE` only after all nine actions are cached or verified; an early stop says `BUDGET_STOP`. A cluster bootstrap interval is returned only with at least two independent bank clusters; shared cases or ambient bands are not counted as independent clusters. Any unresolved reference candidate makes the aggregate panel `UNRESOLVED_PANEL`. This tool does not infer a continuous global optimum or claim real-Challenge regret. Selection of an incumbent policy or portfolio belongs to separate development calibration; taking the better competitor separately for every held-out job would be hindsight selection.

An explicit `--producer-trace RESTRICTED_LOCAL_PATH.json` creates, exclusively, a trace with sequence/order, policy/condition identities, digest of the observed prefix at every proposal, candidate digests, typed observations, attempt kind and costs, warm/cache provenance, cumulative wall/core/evaluation spend and stop reason. It contains per-case reference values and **must remain producer-only**. Default stdout contains no case IDs, proposed actions, winners, margins or reference values. No hidden bank, AX42, LIVE or miner disclosure is authorized by this development tool.

The existing `equal_budget` fixed-order curves retain their historical meaning. A new held-out panel, independent custody receipt, complete costs, reference resolution, calibration of realistic competitors, and buyer-approved action/decision law are still needed before any value-bar or commercial claim.
