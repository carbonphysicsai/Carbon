# Carbon-owned design optimizers — eight-Challenge DEVELOPMENT design

This index gives the requested **buyer-decision optimizer proposals** in the required order. Each linked file is one Challenge specification. The [round-one customer packets](../round1/README.md) own the buyer requirements; the optimizer proposal does not alter a Score Pack, grader, hidden pool, validator, LIVE contract, miner surface or product qualification. The Test Lead owns how a decision is scored, attacked and statistically qualified. **HUMAN_INPUT (recommended)** denotes a planning value that is not in the packet and is not approved for an official batch. **NOT_DEMONSTRATED** denotes missing reference, power, product or cost evidence. A finite-bank optimum means only best within that exact registered bank.

## Shared decision contract to implement later

The task brief names `carbon/design_search/tasks.py`, but that file is **absent on the inspected `main`**. Existing [Challenge-neutral `SearchAdapter` freeze/commit machinery](../../../../carbon/design_search/experiment.py) and [finite `Problem`/reference patterns](../../../../carbon/design_search/track_b.py) are reusable (KEEP/WRAP); they do not yet express all eight buyer tasks or create the missing interface. No interface code is changed here. A prospective Challenge-neutral extension should register, as one immutable task identity:

1. Challenge and decision-contract versions; action grammar, validity and canonical finite-bank/lattice identity; producer-owned initialization/seed and query budget.
2. An outer buyer-job identity and its approved `P_job`, protected proposal law `Q_job`, job-level evidence weight and clustering key, distinct from the inner condition panel's `P`, diagnostic `Q` and weighting. A robust aggregation rule checks every mandatory within-job case before ranking. Different seeds or probes of one unchanged brief never create new job identities.
3. Objective quantity, direction and **physical unit**, lexicographic secondary objective, explicit hard limits and numerical uncertainty/refinement bands, tie rule and `NONE_FEASIBLE`/`UNRESOLVED` states.
4. Model-output/observer version, pinned reference-bank or case identities, common resolved mask, cost ledger, commit-before-verification record and disclosure boundary.

An optimizer consumes only model predictions within its frozen budget and commits the selected action before reference access. The producer alone controls official starts, hidden scenario draws and protected truth. A second registered optimizer is an **audit of path sensitivity**, not a license to change the primary rule after observing a model. The buyer's design tool can use the same action grammar, objective and optimizer version while returning uncertainty and requiring independent final verification. It must not receive protected evaluation identities or label data.

Physical regret is defined only relative to a fully reference-resolved, feasible comparator in the **same exact bank/task**. Hard-limit violations, correct/incorrect abstention and reference/infra failures are distinct outcomes. Close calls use prospective refined truth; if still unresolved, Test Lead must pre-register the uncertainty handling. A pessimistic scoring backstop may withhold favorable evidence, but cannot label missing reference/infra work as candidate scientific failure. The requirements to challenge edge optimism, over-caution, sign errors and optimizer-aware localization are in every spec; the Test Lead chooses the attack implementations, score use, error target and hidden-batch size.

## Blocked before a reference-judged hidden batch

1. **Battery, Motor and Cooling design-space revisions.** Current packets specify buyer limits but do not demonstrate a feasible design under their current action spaces. Battery additionally lacks the prospective SOC-time/full-programme observers; Motor needs command-specific torque/cogging binding; Cooling needs revised assembly grammar and qualified full-plate or composition truth. Freeze these changes prospectively; do not relax buyer limits to fit existing solved points.
2. **Reference capacity for f02/f06/f08/f13/f17.** Their selected first-round grants are bounded feasibility work. Per-case costs for Elmer, 3D full-wave, CalculiX, Helmholtz and flow/scalar solves remain unmeasured; full bank production needs a separate quote, grants, retained ledger and numerical adequacy. f06's fine-grid memory and f13's frequency-launch count are especially consequential.
3. **Task-population and power authority.** Each packet §3 now sketches buyer-recognizable *job* variation and recommends a small scoping inventory. No outer `P_job`, protected `Q_job`, job-level weights or sufficient hidden `n` has been adopted. f02's 24 strata are also conditions of one package, not 24 independent buyer jobs. Multiple curves, wavelengths, cycles, frequencies or correlated conditions are not independent design tasks. The Test Lead and owner must establish the separation target, clustering and power on eligible, reference-covered jobs; scoping inventories and optimizer pilot counts do not establish statistical power.
4. **Shared interface.** The requested `tasks.py` is absent; a later, authorized implementation must reconcile these specifications with the current neutral search/commit machinery. This document does not widen execution freedom or alter historical decisions.

**Maturity:** buyer requirements and optimizer proposals are `SPECIFIED` only. Reference adequacy, feasible-bank coverage, power, customer latency, scientific qualification, security qualification, product qualification and `LIVE` are **NOT_DEMONSTRATED**. Existing historical Battery, Motor and Cooling evidence retains its own version and meaning.
