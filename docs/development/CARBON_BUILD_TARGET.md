# The Carbon we are building

Owner-approved build direction, 17 October 2026. This records Ryan's lean
operating vision and guides implementation. It is not another runtime contract,
permission service or claim that the target is already delivered. Existing
scientific, security, economic and release authorities keep their actual scope.

## The purpose

Carbon finds better ways to make fast physical models. Miners explore broadly;
validators independently reconstruct; Carbon controls the test. A useful model
satisfies the Challenge's physics/constraints and accuracy requirements, then
competes on the declared performance objective against the solver.

## The normal flow

1. **Get the Challenge kit.** It supplies the job and input/output contract,
   fixed TRAIN material, public generator/reference solver, practice tools,
   physics/accuracy requirements and declared resource/reproducibility rules.
2. **Experiment freely on owned compute.** Use open-source libraries, languages,
   backbones, optimizers, losses, curricula, ensembles or architecture-building
   graphs. Use a preferred editor/agent; Graphite is an option. Miners and
   validators each use their own compute. The catalogue offers examples and
   caches, never backbone permission. Public research does not wait for an
   unrelated official receiving validator or physical qualification campaign.
3. **Submit one reproducible construction recipe.** Pin source and dependencies;
   declare the build procedure, TRAIN use, output interface and actual resource
   request. No submitted pretrained checkpoint or undeclared learned asset is an
   authoritative starting point. Cache/provision dependencies internally; the
   miner should not hand-carry an image/receipt chain between operators.
4. **Rebuild independently.** A fresh disposable worker constructs from the
   fixed Challenge TRAIN and declared initialization under enforced limits. It
   has no hidden exam answers/metadata, judge authority, credentials or network.
   Public reconstruction tests run the actual same procedure on public material;
   never silently substitute a simpler base model.
5. **Freeze and test.** Transfer bounded numeric state and supported mathematical
   inference into a separate isolated runtime. No participant Python imports,
   pickle, executable hooks or participant grading callbacks enter the judge.
   Carbon retains references/hidden metadata and computes the measurements.
6. **Retain and transport.** Keep native state, original inputs/targets/predictions
   and source/environment/data/recipe/seed lineage in the existing ScoreLab bank.
   Send the versioned eligible result through the existing Bittensor path.

Source/dependency assets may not smuggle pretrained weights. Fresh execution and
provenance checks enforce declared ingress; they cannot conclusively prove that
arbitrary source encodes no learned information. Do not disguise this limitation
with construction levels. Export/runtime incompatibility is a concrete adapter
problem, not a permanent backbone approval category or a universal support claim.

Each Challenge owns its **physics contract**: physical scope, governing
relationships, assumptions, boundary and initial conditions where applicable,
quantities and units, constraints, reference applicability and acceptance rules.
The shared platform binds and enforces that versioned contract; a backbone,
runtime or another Challenge cannot supply its physical acceptance. Shared
gate execution does not make the physics contract universal.

## One scoring implementation

ScoreLab remains a thin workbench over the same versioned ScoreEngine and
Challenge Score Pack as validators. Its core comparison is the **model design
versus the solver on the same job and required fidelity**:

- Apply the Challenge's mandatory physics/constraint gates.
- Check solver-reference accuracy using its actual metrics, units and coverage.
- Among eligible candidates, apply the declared performance objective using
  measured latency/throughput/memory and an honest solver baseline. Report
  construction/training cost separately; cached reference reads are not solver
  runtime. If no ranking rule exists, report the tradeoff without inventing one.

Missing/reference/infra evidence stays typed and unresolved, not zero or model
failure. All adverse outcomes remain represented. Equal authorized measurements
and the same pack produce the same result in ScoreLab and validator adapters.
Generalize the machinery across Challenges; do not pretend their raw scores are
scientifically interchangeable. Preserve historical v1 semantics and evidence.
Buyer-value tau/N1, retrospective survivor menus and expanding oracle grids are
not prerequisites for this core. An explicit future Challenge may use them.

## Keep the good wiring; remove the extra machinery

Keep working Bittensor identity/authentication, metagraph/UID handling,
submission/result transport and eligibility/weight-publication safeguards.
A benchmark number alone never authorizes a weight write. This design introduces
no live economic policy, chain operation or deployment permission.

Reuse the dependency cache, isolated worker, graph lowering, TRAIN loader,
state retention, existing model bank and scoring engine. Remove level/family/
combination permissions, duplicate reducers/trackers, manual staging chores and
redundant approval chains as their callers are replaced. Historical readers
need an actual consumer. Relocation is not deletion; a simplified screen over
the old restrictions is not simplification. Add a layer only for a distinct
necessary boundary or demonstrated requirement.

## Guided autonomy and the finish line

Each team owns a complete outcome and the reversible engineering decisions
inside it. Launchpad integrates and owns delivery; Platform owns recipe/build/
export; environment work owns pinned provisioning; ScoreLab owns the common
benchmark/scoring path; Product owns actual validation/cleanup. Research owns
scientific applicability; Bittensor work preserves the proven network seams.
Root protects scope and resolves cross-team conflicts, not routine choices.

Teams also have cleanup authority in their owned areas: delete obsolete source,
callers, permission UI/API paths, duplicate documents and unused abstractions as
part of the tested replacement. Replace tests whose sole contract is the retired
permission model with tests for the new behavior and real boundaries. Do not
delete a failing security/scientific invariant or erase model/evidence history.
Coordinate shared-path removals with their owner; no new cleanup committee or
per-file Root permission is required. Unrelated purges remain out of scope.

Teams choose implementation details, fix findings, integrate ready artifacts
and select meaningful tests without per-step Root approval. Coordinate directly
through authorized channels when an interface changes. A receiving ACK matters
only for the dependent action. Escalate a true scope conflict, cross-team
deadlock or reserved science/security/economic/release decision once, with a
recommendation; continue independent work. Never bypass an actual rejection.

Completion is the normal user flow: real recipe, independent fresh build,
protected inference/evaluation, solver benchmark and retained model, with the
obsolete permissions absent from that path and relevant Bittensor regressions
passing. Test authentic operator backbones and a noncatalogue graph. A schema,
import, GPU probe, custody ACK or source-only adapter cannot replace that flow.
Report what is implemented and tested separately from what is qualified.
