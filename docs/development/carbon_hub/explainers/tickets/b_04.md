# B-04: Reference and truth contracts

**Wave:** B

**Map ref:** `WAVE-B/B-04`

**Status:** IN_PROGRESS

**Target phase:** WB-1/2

## What and why

Define ReferencePolicy, TruthAsset, primary and witness runner interfaces, applicability, uncertainty, independence, disagreement, and typed reference failures.

A candidate can only be judged against a registered and adequate source of truth. Carbon also needs explicit behavior when the required reference cannot answer or fails.

## What it adds

The truth authority boundary that measurements and qualification consume.

## Placement and handoff

- **Depends on:** B-02A, B-01F, B-02A directly precedes the bounded engineering contract, B-01F conditionally gates resumption of the runtime phase after contract ratification
- **Feeds:** B-01F, B-05, B-06, B-07F, B-E1, B-E2, B-GATE
- **Driver:** Codex + SciML
- **Review route:** SciML + statistics + protocol + independent reviewer
- **Master questions:** MQ-004

## Explicit non-goals

It does not declare a solver universally authoritative or permit silent fallback to an unregistered reference.

## Current stage

B-01F's exact completion predicate is satisfied and B-04 remains the selected in_progress runtime ticket. GOV-REVIEW-01 interposes only the prospective delivery-review migration: fresh complete-diff Codex/GPT review, distinct non-author human approval, and the protected GPT review gate. It changes no B-04 runtime semantics or maturity.

## Maturity ceiling

SPECIFIED and RATIFIED_ENGINEERING_CONTRACT are earned for the bounded engineering contract. IMPLEMENTED, runtime TESTED, REFERENCE_QUALIFIED, scientific, security, network, commercial, production, and LIVE states remain unearned until B-04's exact completion predicate passes.
