# B-04: Reference and truth contracts

**Wave:** B

**Map ref:** `WAVE-B/B-04`

**Status:** IN_PROGRESS

**Target phase:** WB-1/2

## What and why

Define ReferencePolicy, TruthAsset, primary and witness runner interfaces, applicability, uncertainty, independence, disagreement, and typed reference failures.

A candidate can only be judged against a registered and adequate source of truth. Carbon also needs explicit behavior when the required reference cannot answer or fails.

## What it adds

The truth authority boundary that measurements and qualification consume.

## Placement and handoff

- **Depends on:** B-02A
- **Feeds:** B-05, B-06, B-07F, B-E1, B-E2, B-GATE
- **Driver:** Codex + SciML
- **Review route:** SciML + statistics + protocol + independent reviewer
- **Master questions:** MQ-004

## Explicit non-goals

It does not declare a solver universally authoritative or permit silent fallback to an unregistered reference.

## Current stage

Version 1.0 records B-03 done in bounded merged engineering scope and selects B-04 in_progress for working-contract authoring only. The B-04 contract in this snapshot is a candidate; normal merge and exact-main CI remain pending, and no B-04 implementation is authorized.

## Maturity ceiling

SPECIFIED only as a candidate bounded engineering contract. RATIFIED_ENGINEERING_CONTRACT, IMPLEMENTED, runtime TESTED, REFERENCE_QUALIFIED, scientific, security, network, commercial, production, and LIVE states remain unearned.
