# B-07D1: PriorPack schema and immutable store

**Wave:** B

**Map ref:** `WAVE-B/B-07D1`

**Status:** DONE

**Target phase:** WB-3/4

## What and why

Define PriorPack, estimands, exact immutable storage and indexing, receipts, and an offline compatibility projection.

A miner prior needs a stable Challenge-level data contract and exact historical identity before Carbon can publish or serve any content.

## What it adds

Immutable canonical PriorPack storage, exact validation and authorization, acyclic history/index snapshots, withdrawal-preserving audit history, and a private offline v2-to-v1 compatibility projection.

- **Depends on:** B-07A, B-07B, B-07S, A6, A9, A11
- **Feeds:** B-07D2, B-07D3, B-E4, B-GATE
- **Driver:** Codex + Landscape
- **Review route:** Science + security + protocol
- **Master questions:** MQ-016, MQ-018, MQ-025, MQ-026, MQ-045, MQ-051

## Explicit non-goals

It does not publish a qualified learned prior or personalize bytes by miner.

## Current stage

PR #95 accepted and normally merged D1 with D2/D3; D1 is done in bounded immutable-store and private-projection scope.

## Maturity ceiling

SPECIFIED, IMPLEMENTED, and TESTED are earned only for immutable private storage, authorization seams, history, and offline private compatibility. No public publication, production signer, scientific/security/rights qualification, or LIVE authority is earned.
