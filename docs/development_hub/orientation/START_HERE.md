# Start Here: Carbon Development Hub

## Carbon in one minute

Carbon is building an incentivized experimental system for discovering, independently testing, learning from, and qualifying methods for constructing fast physical models.

The development plan follows one governing sequence:

```text
prove the judge
then prove the portfolio
then deepen the physics
then widen the search
bring industry in throughout
```

Carbon organizes development into **waves** and **tickets** so the team can widen capability without silently widening authority.

- A **wave** states the system outcome Carbon is trying to earn.
- A **ticket** owns one bounded unit of authorized work inside the active wave.
- A **decision record** explains why the team chose an approach and how to change it.
- A **PR** contains the exact implementation and review history.
- An **evidence record** states what the merged result proves and what it still does not prove.

## How to use the hub

1. Open the wave to understand the system outcome and authority ceiling.
2. Open the ticket to understand the bounded purpose, why it matters, dependencies, and handoff.
3. Follow the repository links for exact scope, code, decisions, tests, review, and evidence.
4. Place a new decision, bug, adjustment, or protocol proposal on one primary wave and ticket before implementation.
5. Update the hub after the repository changes status, dependency, ownership, or authoritative links.

## The boundary

**Hub:** what, why, where, status, dependency, and navigation.

**Repository:** how, exact semantics, implementation, tests, review, evidence, and authority.

The hub never promotes a design, fixture, implementation, or test into a scientific, security, network, commercial, or production claim.
