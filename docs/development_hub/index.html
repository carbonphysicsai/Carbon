New to Carbon

Read this before opening a ticket or PR. The hub supplies context. Repository authority supplies exact meaning.

What Carbon is building

Carbon is an incentivized experimental system for discovering, independently testing, learning from, and qualifying methods for constructing fast physical models.

Why waves exist

Each wave earns one bounded system capability. Later architecture cannot be treated as implemented merely because the plan describes it.

How to read the work

Wave: the system outcome being earned. Ticket: the bounded authorized change. Decision: the recorded choice and change path. PR: implementation and review. Evidence: what passed and what remains unearned.

Where detail lives

Use the hub for what, why, where, status, dependency, and orientation. Use the repository for how, exact semantics, code, tests, review, and evidence.

A Wave A: Bounded protocol skeletonProve Carbon's software authority boundaries before real scientific execution. closed
What

What this wave is

Wave A creates the smallest bounded protocol skeleton that can express a Challenge, a declarative strategy, protected randomness, scoring, submission lifecycle, public-safe disclosure, miner-facing operations, observability, and invariant checks.

Why

Why Carbon needs it

Carbon cannot trust later scientific or network behavior until the software keeps producers, evaluators, public views, protected data, and economic state in separate authority domains.

Success

What success means

The A-1 and A0-A12 tickets close in their recorded engineering scopes, the invariant suite passes, and the repository can demonstrate the intended boundaries with fixture-only behavior.

Boundary

What it still does not mean

Wave A closure does not create scientific, security, network, commercial, production, LIVE, launch, frontier, settlement, weight, or emission authority.

Unlocks

Wave B can build science-ready authoring and research contracts on a stable substrate instead of inventing basic lifecycle and authority semantics again.

B Wave B: Science-ready authoring skeletonsMake one scientific exam authorable and the miner research loop executable with fixtures. active
What

What this wave is

Wave B defines the contracts and fixture implementations needed to describe the physical job, generate canonical cases, register truth, define measurements, compile strategies, bound resources, run nominal research and practice, issue receipts, stage priors, and assemble qualification evidence.

Why

Why Carbon needs it

A real Challenge needs an exact scientific object before Carbon can reconstruct and evaluate a real candidate. Wave B removes ambiguity from the exam and research interfaces while keeping unqualified behavior unavailable.

Success

What success means

Carbon can demonstrate the board's fixture-only chain from public scientific contracts through a resolved plan, nominal practice and research records, a fixture-official reconstruction path, TEST_ONLY prior handling, and a dossier that still fails closed for LIVE.

Boundary

What it still does not mean

Wave B does not include real miner training, production reconstruction, authenticated remote transport, official scientific evidence, LIVE activation, network weights, or learned public priors from official outcomes.

Unlocks

Wave C can connect one real candidate to one real, qualified single-Challenge execution path.

C Wave C: Real single-Challenge integrationRun one real candidate through one real end-to-end scientific path. planned
What

What this wave is

Wave C replaces fixture-only seams with one real vertical integration: a registered Challenge, qualified population and SamplingPlan, real reconstruction, protected evaluation, measurements, a Score Pack, and evidence provenance.

Why

Why Carbon needs it

Contracts and fixtures can expose architectural mistakes, but Carbon must prove that one real candidate survives the full operating path under real resource, sandbox, reference, and validator constraints.

Success

What success means

One candidate moves through the registered Challenge, producer-independent reconstruction, protected evaluation, and ExperimentRecord chain with real adapters and testnet-capable transport.

Boundary

What it still does not mean

Wave C does not itself authorize LIVE status, broad Challenge coverage, final frontier economics, or mainnet settlement.

Unlocks

Wave D can make the human scientific judgments required to activate the first LIVE exam.

Claim discipline

Eight independent maturity states

Carbon does not infer a later state from an earlier one.

01

Specified

A contract or design says what the object or behavior should mean.

Proof

Owning specification, ticket, or ratified decision.

Does not imply

No implementation, test, qualification, or production claim follows.

02

Implemented

Code or an operational artifact exists in the bounded recorded scope.

Proof

Exact implementation identity and merged change.

Does not imply

Implementation can still be scientifically wrong, insecure, or unqualified.

03

Tested

The recorded tests passed for the exact implementation and environment in scope.

Proof

Test commands, results, review identity, and evidence record.

Does not imply

Tests do not establish scientific adequacy or production readiness.

04

Scientifically qualified

Qualified evidence supports the registered scientific use or claim.

Proof

Human scientific review, qualified exam inputs, evidence, and exact decision record.

Does not imply

Security, network, commercial, or production qualification does not follow.

05

Security qualified

The relevant threat model, isolation, access, leakage, and failure controls have acceptable evidence.

Proof

Security review and qualification evidence for the exact topology.

Does not imply

Security approval cannot make weak science valid.

06

Network qualified

The transport, participant, validator, and network-economic path has passed its registered tests.

Proof

Localnet or testnet evidence and network acceptance.

Does not imply

Network operation cannot create scientific merit.

07

Commercially validated

Customers have supplied real evidence that the product and delivery model solve a valuable problem.

Proof

Customer discovery, paid work, repeat delivery, expansion, or recurring evidence as applicable.

Does not imply

A design-specified SKU or scenario is not traction.

08

Production qualified

The exact end-to-end system, context, controls, and operations have passed the production gate.

Proof

Recorded production qualification and activation authority.

Does not imply

Qualification remains bounded to that exact version, context, and limitations.

Plain language

Glossary

Use these definitions for orientation, then follow the source links for normative detail.

Wave

A bounded stage in Carbon's development sequence with a system outcome, authority ceiling, and closeout gate.

Ticket

The smallest authorized unit of work on an active wave board. It owns scope, dependencies, reviewers, non-goals, and definition of done.

Decision

A durable choice with rationale, alternatives, affected interfaces, reversibility, and an exact change or supersession path.

PR

The exact repository change where implementation, review findings, repairs, tests, and merge identity live.

Evidence record

The durable proof for what passed, at which identity, in which scope, and with which maturity ceiling.

Challenge

A registered physical job and its population, case, truth, measurement, evidence, disclosure, and lifecycle contracts.

LIVE

An exact activated scientific state. Documentation, fixtures, code, or tests cannot imply LIVE.

Fail closed

Keep an affected capability unavailable or return a typed unresolved or infrastructure outcome when required authority or evidence is missing.

PriorPack

An immutable Challenge-level research-orientation artifact. Wave B keeps learned public publication unavailable and uses TEST_ONLY staging.

Frontier event

A later-wave record that a contender moved the verified scientific frontier under a registered promotion policy. It is not the same as leaderboard rank.

Map reference

A stable hub location such as WAVE-B/B-03 used to place a decision, bug, risk, or evidence update.
