# Carbon contributor and agent tools

Start with [AGENTS.md](../AGENTS.md), the current authorized task and relevant
code/specifications. The [execution overview](EXECUTION_PROTOCOL.md) and
[ticket startup](CODEX_TICKET_LAUNCHER.md) point to those same rules; they do not
add another checklist.

| Source | Purpose |
| --- | --- |
| [Constitution](../CONSTITUTION.md) | Domain authority and durable boundaries |
| [Invariants](../.agent/INVARIANTS.md) | Scientific/security constraints |
| [Build target](../docs/development/CARBON_BUILD_TARGET.md) | Current lean construction, independent evaluation and shared scoring outcome |
| [Wave record](../.agent/WAVE.md) | Status/dependencies; new direct assignments may supersede old selection |
| [Delivery](../.agent/DELIVERY_PROTOCOL.md) | One source for checks and merge defaults |
| [Decisions](../.agent/DELEGATED_DECISION_PROTOCOL.md) | Delegated engineering and reserved human decisions |
| [Environment](../docs/development/ENVIRONMENT.md) | Maintained setup and canonical validation |

Use coherent changes, actual tests and concise evidence. Current human conditions
and enforced protections remain controlling. Historical Hub maps, Wave snapshots
and receipt templates are not active prerequisites. Passing software checks
does not qualify science, security, economics, deployment or launch.

Optional harness integrations live in [executors/](executors/). They cannot
override repository instructions; `agent_pack/.agent/` is retired.
