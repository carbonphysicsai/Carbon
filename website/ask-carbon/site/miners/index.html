01 / The Research Opportunity

You propose the method. Someone else runs the exam.

A miner is a researcher or developer who proposes a method for building a fast physical model, under the rules of a challenge. You don’t submit trained weights. You submit a reproducible design: the training strategy, its configuration and everything an independent evaluator needs to rebuild it from scratch.

The launch scope is neural operators, chosen because they give a concrete, reproducible first market. The architecture is built to widen that space over time, from parameters to strategies, architectures and eventually new construction methods, without changing who controls the grade. Early miners get the widest frontier and the fewest incumbents.

A design

A strategy that can be re-run: backbone, training procedure, hyperparameters, data handling, seeds, resource budget. Its advantage has to survive someone else executing it.

Not weights

An opaque trained artifact whose producer controls the evidence behind it. Carbon does not score these.

02 / From Challenge to Submission

Read the contract. Practise. Submit the strategy.

  1. 01

    Read the challenge

    The problem, the input/output contract, the operating range, the resource limits and the scoring rules. Every score has scope: performance inside one challenge says nothing outside its declared envelope.

  2. 02

    Run permitted practice

    Compare methods and validate your design on practice cases. Practice feedback is yours to learn from; the official score comes from the protected exam.

  3. 03

    Submit the allowed strategy

    Evaluators control official reconstruction and the protected test cases. You never see the seeds, the realised stress cases or the answer key, and neither does anyone else.

05 / Evaluation and Rewards

Physics first. Then rank. Then reward.

  1. 01

    Independent reconstruction

    A validator rebuilds your candidate from the design, on validator-controlled data, inside the challenge’s resource limits.

  2. 02

    Reference comparison and mandatory physics checks

    The rebuilt model is compared to the challenge reference and put through the mandatory, challenge-specific physics gates. Fail a gate and the result is inadmissible, whatever the average accuracy.

  3. 03

    Robustness within scope

    Registered stress tests on protected cases probe behaviour under changed conditions, inside the declared operating range.

A strong average score cannot compensate for a mandatory physics failure.

Score, frontier and reward are three different things. A score ranks admissible candidates. A verified frontier advance is an evidence state, established against the incumbent on the same fresh exam. Reward settles only on a verified advance. Carbon pays for verified progress, not incumbency.

06 / Start a Development Run

Three commands to a working environment.

  1. 01

    Open the Dev Container

    Clone the repository and open it in the canonical Ubuntu 24.04 Dev Container. Everything below runs inside it.

    git clone https://github.com/carbonphysicsai/Carbon
cd Carbon
  2. 02

    Bootstrap and check

    Sync the environment, then let the doctor confirm it matches what validators run.

    ./scripts/dev/bootstrap.sh
./scripts/dev/doctor.sh
  3. 03

    Run the example

    Pick a versioned example and run it. A passing doctor and a completed example run mean you are ready to write a design.

    ./scripts/dev/canonical.sh --full
