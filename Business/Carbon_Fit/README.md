## Decision in one page

Assess a complete opportunity: **client job + intended claim + deployable baseline + candidate construction + reference + resource/cadence profile**. Use six checks: job/access, reference, construction, exam, deployment and value. Preserve unknowns and blockers. Rank the next decision-changing investigation, not architectures by a universal fit percentage.

A fast acceptable numerical method can be the right client solution. Include it as the deployable baseline. A reference cache can make repeated comparison cheaper without making new physical solves cheap. Different Challenges can use different budgets and cadence; scientific adequacy does not become optional in a slower program.

Before an actual execution profile opens, its owners must choose and enforce finite resource ceilings and failure rules. This package selects no runtime value. For reference reuse, first investigate a bounded cohort whose candidates freeze before they can learn anything from its protected evaluation. A persistent hidden reservoir needs a separate reuse and leakage qualification. Do not distribute a plaintext answer bank to arbitrary validator hosts and describe it as secret from those hosts.

The client website is an intake and preliminary analysis tool. It does not qualify a model or exam. It should provide value without requiring contact details, then offer an explicit action to send the reviewed inquiry to Carbon. The proposed receiving workflow uses a private durable record and retryable staff notification. No collection endpoint exists as a result of this documentation.
