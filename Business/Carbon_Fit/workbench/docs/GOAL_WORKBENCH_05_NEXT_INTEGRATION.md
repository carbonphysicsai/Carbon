# GOAL-WORKBENCH-05 next-integration decision

## Decision

Prepare, but do not implement or dispatch, one source-owned read-only capability and evidence-applicability response interface.

The interface should accept an exact workbench job/design revision, route, intended-use delta, evidence identities, dependency domains, and the one consequential question. A source owner may return capability coverage, scoped evidence applicability, unresolved conditions, provenance, and a restart event. The workbench may display that result only after exact identity/schema validation.

## Why this is next

The three demonstrations show that exact source/capability identity and owner response state are the repeated manual seam. A bounded read interface would reduce re-entry while preserving the distinction between local planning, native execution evidence, scientific applicability, rights/use authorization, and customer outcome.

## Owner and restart event

Owner: the existing source owner for the referenced capability or evidence domain; no new global owner is created here.

Restart event: an owner-accepted closed response contract with explicit trust/provenance rules and one public fixture. Until then, the existing manual handoff and external-linked record stay labeled manual/external.

## Exclusions

This decision does not authorize GitHub polling, CRM/Grok/calendar/email writes, customer transmission, solver/campaign execution, D-02/D-03/D-04/D-05 work, cell-7 or witness follow-up, the 72-member C-05 campaign, protected answers, scientific qualification, product qualification, scoring, launch, or a new orchestration backend.
