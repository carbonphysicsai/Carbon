## Ticket questions

**Did routing remove unnecessary Challenge-authoring steps?** Yes, within the synthetic existing-capability journey. The route produces an intended-use/deployment review while native authoring remains untouched. This is a workflow observation, not evidence that any real capability is suitable for a customer.

**Can the owner see one next decision without reading the full job?** Yes. The console row shows route, owner, lead, three status axes, primary action/decision, blocker, restart event, and provenance. Attention buckets are deterministic groupings, not priority ranks.

**Did change impact preserve valid evidence while staling affected evidence?** Yes in the declared scope. Editorial changes preserve numerical applicability; population changes retain fixed-case history while removing population inference; output/units, measurement, reference, physics, authoring, generator, or reconstruction changes mark dependent bindings for review. Rights, disclosure, intended use, and deployment remain separate from numerical validity.

**Which statuses still rely on manual assertions?** Route selection, accountable owner/lead, customer disposition, locally entered blockers/restart events, external record links, and unresolved rights/use statements remain manual unless an exact native result is imported. C-05 provenance is native imported; its scientific decision is unresolved. Source-owner confirmation and authorization are unavailable to browser fields.

**What caused the most repeated manual work?** Supplying exact source/capability references and re-entering the bounded owner handoff/provenance around evidence that has no source-owned read interface. No measured time or cost claim follows from the synthetic demonstration.

**What should be automated next?** Add one read-only, source-owned capability/evidence-applicability response interface, if its owner accepts the schema and trust boundary. It should return exact identities and scoped decisions without adding GitHub polling, writes, execution, qualification, or launch. See `GOAL_WORKBENCH_05_NEXT_INTEGRATION.md`.
