## 1. What was built

A self-contained browser prototype connects the supplied science-backed GTM atlas to job-specific feasibility analysis, reference planning, experimental records and client discovery. It provides a searchable 64-opportunity atlas, three-way source comparison, one-validator recurring-work calculator, six-check review, role-specific reference planning, experiment/report library, client-brief preparation and local export/import.

The complete offline source, data, draft schema, importer, build script, UI and tests are delivered in the conversation artifact `Carbon_Physics_Opportunity_Workbench_v0_1.zip`. The entry artifact is `Carbon_Physics_Opportunity_Workbench_v0_1.html`. These are downloadable conversation artifacts, not deployed repository assets or an accessible production website. This PR records the design and machine-readable source index; Engineering owns integration of the reference implementation. No production code is added here.

The prototype does not run solvers, launch experiments, optimize operating profiles, ingest protected data, or confer evidence authority. Earlier research reports are indexed, not numerically revalidated by this build.

## 3. The unit of analysis

Evaluate a **client job + physical claim + target population + deployable baseline + candidate construction + reference architecture + resource profile**. A PDE label or source rating is insufficient.

Production should separate these objects:

| Object | Purpose | Authority ceiling |
|---|---|---|
| OpportunitySourceRecord | Source hypothesis, original text and provenance | Research orientation |
| ScopedJobProposal | Customer decision, physical mapping, baseline and intended claim | Proposal |
| ReferenceRolePlan | Method, role, implementation, regime, evidence and cost | Plan unless exact qualification supports it |
| ProfilerRun | Protocol, hardware, clocks, observations, artifacts and failures | Scoped research observation |
| OpportunityReview | Six checks, next test and investment decision | Human decision support |
| QualificationReference | Exact signed/versioned domain qualification reference | Inherits only the source authority |
| ClientInquiry | Customer assertion and permitted follow-up | Customer-reported, unreviewed |

Keep external scientific results, Carbon hypotheses, proposed experiments and qualified Carbon evidence separate. Store development measurements as unqualified supporting observations. An imported report, software test, simulation, source rating or customer assertion cannot become qualified Carbon evidence through the UI.

Seven earlier supplied reports are indexed with hashes and method labels. Their numerical results were not re-audited, pooled or generalized to the 64 physics rows. Zero qualified results are imported into this workbench; that is not an organization-wide qualification claim.

## 4. Reference architecture and MMS

Represent method family, scientific role and access/storage mode separately. Caching and customer hosting are not scientific reference types.

Role plans cover verification, construction data, routine exam, independent witness, physical anchor and protected audit. For each applicable role retain the model, IC/BCs, geometry, units, envelope, implementation/configuration, convergence/calibration evidence, uncertainty, independence/correlation, runtime distribution, failure/retry/fallback behavior, hidden-case generation, custody/reuse policy, implementation burden and validation burden.

MMS provides an exact answer to its manufactured problem. It can verify implementation paths, adapters and measurements, and can supply construction data under a declared data contract. It can serve an exam whose registered target is that manufactured family. It cannot silently substitute a manufactured forcing/condition population for the customer population. MMS alone does not validate a closure, constitutive law or physical customer system.

Knowing the manufactured answer does not make the solver verification run free. Record manufacture, differentiation, compilation, materialization and solve costs separately. Qualify the induced source/BC distribution. Protect latent solution coefficients and answer expressions from candidate inputs unless the task explicitly permits them. A numerical witness that shares generated code can share its defects.

## 5. Implemented scenario arithmetic

One validator is fixed. Its compute pool is the variable. Require a named homogeneous hardware/concurrency profile and matched worker-time units. Do not add CPU and GPU timings without a qualified mapping.

For each entered low/high scenario define:

- r: reconstructions per proposal;
- T: fresh training-reference work per reconstruction;
- B: reconstruction work per reconstruction;
- E: inference and mandatory measurements per proposal;
- O: other recurring work per proposal;
- P: promotion work reserved per proposal;
- R: complete evaluation-reference cohort work;
- b: proposed committed candidates per cohort;
- H: usable matched worker-hours/day across the validator's pool.

Non-shared work is `c = r*(T+B)+E+O+P`. Find the largest integer n satisfying:

```text
n*c + ceil(n/b)*R <= 3600*H
```

Apply entered proposal supply if known. Charge a partial final cohort in full. Require explicit inputs, including justified zeros. Reject negative, nonfinite, reversed-range and invalid count values.

This computes scenario capacity bounds, not measured live throughput, a confidence interval, queue latency, discovery productivity or an optimum. Low/high inputs are not p95 bounds. Reuse entitlement remains a separate decision. Repetitions are not distinct proposals. A real operating-point optimizer still needs experimental traces, independent campaign confirmation and load calibration.

One-time qualification money, risk and onboarding duration never enter recurring capacity. Required training labels, reference refresh, unsuccessful attempts, operational overhead and promotion work belong in recurring inputs. The optional baseline-latency check compares entered latency only; it cannot establish accuracy or overall client fit.

## 6. Review and authority

Six checks: job/access, reference, reconstruction, exam, deployment and value. Each has UNKNOWN, SUPPORTED_FOR_STAGE or BLOCKED_FOR_SCOPE plus an evidence note. A supported assertion with no note remains an evidence gap. No composite fit score lets cost compensate for missing science.

Planning choices are UNREVIEWED, INVESTIGATE, PILOT_PROPOSAL, PARTNER_DEPENDENT, PARKED and DECLINE_CURRENT_SCOPE. These are human decisions, not scientific qualification states. Record the next test, continue/stop conditions and reviewer/context note.

The producer cannot control the official grade. Commit the exam before protected instances become knowable. Qualify the exam before it qualifies a candidate. Mandatory physical failure remains disqualifying. This workbench cannot change official seeds, sampling, reference fidelity, measurements, scoring, frontier results or historical evidence.

## 7. Client brief and production handoff

The prototype runs without an application server and does not transmit or automatically save answers. A user can export a plain-text draft and import it later. There are no remote scripts, fonts, analytics, session replay, external AI calls, email sender, storage credentials or collection endpoint. Sending is visibly disabled.

Use synthetic or non-sensitive high-level details. No geometry, solver output, dataset, executable code or credential upload is supported. Local workspace import has a bounded closed schema. Imported text is escaped. Mismatched source IDs and forged qualification, submission or reuse states reject. Export files are not encrypted; clearing the page cannot delete downloaded files.

Production work belongs to Engineering through #139. Reuse the existing website stack after identifying it. Establish private durable storage, authenticated staff access, server validation/recalculation, idempotency, receipt and reliable notification. Persist before acknowledging acceptance. Keep public assets separate from private inquiries, experimental records and reference stores. Approve retention/deletion, destination, access roles, incident ownership and collection notices before enabling sending.

Permission to process/respond, aggregate learning, publication and model training are separate rights decisions. A local brief grants none. Customer assertions, reviewer conclusions, measurements and signed qualifications remain distinct. No confidential customer data may enter this public repository.
