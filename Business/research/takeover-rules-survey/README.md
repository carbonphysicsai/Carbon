# Takeovers that let a close improvement win

**TAKEOVER-RULES-SURVEY-01 — recommendation, not adopted policy.** Research
date 2026-10-11. Public sources only. No solver, network experiment or spend.

Recommend **a permissive, cost-bounded nomination screen followed by a fresh,
paired, multiplicity-controlled final on the actual retained model artifacts**.
A small improvement should win when the evidence resolves it; a near-tie should
remain inconclusive. Do not use a large fixed percentage as the anti-copy test.
All numerical choices remain HUMAN_INPUT.

Carbon's present battery rule has **two** improvement barriers. The screen
requires a relative reduction greater than 0.056993107446249414; the final
requires both a paired interval excluding zero and a point improvement beyond
the same margin. Its displayed 5.70% is rounded. Loosening only the screen does
not make a smaller improvement promotable. The final also rebuilds both recipes
under a matched new training seed, testing a different artifact from the one
already deployed. [Pinned implementation and implications](CARBON_CROSSWALK.md).

The useful external lessons are:

- **SN97:** a relative margin reduces noise crowns but excludes small gains;
  a documented sparse-axis migration produced spurious dethronements. Its
  current code is a better authority than its older winner-take-all README.
- **Historical SN120:** paired duels and an absolute floor; a re-sharded copy
  passed file-hash checks and crowned under a selected-positive/pooled-positive
  window rule. A mandatory second win was later removed as too restrictive.
  Its present protocol has changed, so those are dated lessons.
- **SN91 Cascade:** shared-case bootstrap, cohort correction, clustered
  resampling and a tenure-decaying margin. This is the closest implementation
  analogue, not proof that its constants fit Carbon.
- **SN112 Minotaur and Stockfish Fishtest:** compare the two candidates under
  matched conditions; exact tie/secondary-cost rules and valid sequential tests
  are different from repeated uncorrected looks.
- **SN30 Endure:** current primary documentation describes outcome-scored risk
  forecasts, not a model king-of-the-hill takeover. No epsilon rule is invented.

The proposed final separates a **minimum useful gain** from **uncertainty** and
from **copy detection**. A declared gain of zero is an option if the owner wants
any reliably positive gain; a positive floor needs a decision-value rationale.
Freeze artifacts and rules before drawing the fresh panel. Correct for multiple
challengers and repeated attempts, preserve mandatory gates and publish only
allowlisted aggregate evidence. Stored-model testing establishes artifact
performance, not reproducibility of its recipe across rebuild seeds.

The acceptance panel in [RECOMMENDATION](RECOMMENDATION.md) includes null copies,
re-sharding, small real gains, reconstruction noise, regional regressions and
multi-hotkey selection. It has **not** been run here. It must measure both false
takeovers and the chance/latency of accepting a small real gain. No public source
establishes Carbon's live error rate or a universal safe epsilon.

Read the [survey](SURVEY.md), [Carbon crosswalk](CARBON_CROSSWALK.md),
[rule proposal](RECOMMENDATION.md) and [source register](SOURCES.md). Adoption,
security acceptance and economic entitlement are the owner's decisions.
