## Selection and finish

`owner_dev_v1.select_top_three` selects each rule's own k=3 members using fixed
LEG scores and admitted identities only. VALUE is absent from its interface.
Exact LEG ties use lexical IDs and are reported; this is a reversible
engineering tie rule. Missing scores withhold selection rather than shrink n.
The top half is rank <= floor(n/2); tied gamers use best competition rank, so
lexical order cannot hide a gamer below the cutoff. Actual admission/guard
evidence remains required upstream; this helper does not infer gate passes.

`selected_regret_minutes` consumes the bound selection and complete common
VALUE vectors from a registered verified-pick workflow. It reports all three
member vectors, individual means and their equal-weight descriptive mean in
minutes. It never chooses the best VALUE member of the three or a replacement
when a selected outcome is unresolved. Verification costs remain a separate
workflow measure. The helper does not estimate tau, bootstrap uncertainty or
an adoption threshold. Existing `score_proof`/paired C1 analysis remains the
source of those diagnostics; the older single-representative C1 outputs are
preserved and are not relabelled as the new top-three procedure.

No-gamer screening and pick-regret comparison replace tau significance as
selection authority. A complete runtime selection/confirmation receipt still
must bind the exact prospective registration, score form and evidence. One
final holdout reveal remains in Test Engineer custody; this code has no
holdout path or loader. If no candidate survives Stage C, or none beats v2 at
the final confirmation, **keep v2 with quiz shadow** is a completed decision.
Do not reveal a holdout just to exercise an empty shortlist.
