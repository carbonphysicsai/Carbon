# Public demos are also training data

**SHOWCASE-DISTILLATION-RISK-01 — options, not disclosure policy.** Public
research dated 2026-10-11. No live model queries, model training, solver, spend
or hidden/AX42 access.

The literature establishes **no universal safe number of published points**.
Useful copying has been demonstrated with hundreds of oracle labels when the
attacker has suitable unlabeled data; other settings require millions. Those
are different tasks and access models, not a confidence interval for Carbon.
[Experiments and transfer limits](LITERATURE.md).

Carbon's current registered battery showcase has a structural maximum of
**420 unique public inputs, 1,260 continuous values and 420 reach classes per
incumbent artifact**: the development contract's fixed grid and scenarios.
These are source-derived fixed low/base/high counts, not observed live output
counts. Missing predictions reduce actual exposure. The signed feed projects
the whole panel before the browser replay; displayed optimizer steps alone
understate what a downloader can obtain. The leaderboard's rounding setting
does not round this prediction panel. [Source audit](EXPOSURE_AUDIT.md).

For that published finite grid, a lookup table can reproduce the disclosed
predictions without learning the recipe. Off-grid or hidden-case performance
remains unknown. A four-input quadratic function has only a small coefficient
count; the public grid can identify that function class if it fits. This is an
explicit mathematical scenario, not evidence the incumbent is quadratic.

**Recommended option for owner consideration:** a fixed, cumulatively bounded
public replay on a small declared input set, showing the decision, solver-verified
outcome, aggregate errors and adverse findings; withhold the full live numerical
prediction table and broad downloadable traces until a selected publication
stage. A full optimizer replay necessarily reveals every queried prediction
sent to the browser. Use a deliberately open demo/control if unrestricted
interactive exploration is the commercial priority. No point cap or delay is
adopted by this research.

The trade-offs in [OPTIONS](OPTIONS.md) are explicit:

- **Fewer fixed points** reduce exposure; rotating small sets silently rebuilds
  a large corpus. A smaller demo shows less generality.
- **Coarser values** weaken some attacks but can still train an approximation,
  and can misrepresent decisions near a hard limit.
- **Delay** postpones copying, leaving eventual information unchanged.
- **After dethronement** protects the current tenure initially, but predecessor
  labels can still help copy a closely related successor.
- **Errors against public references** are not automatically safer: signed
  residuals reconstruct predictions exactly; absolute errors restrict them to
  alternatives, and aggregate errors expose much less per-case information.

A proposed public-only leakage/value experiment would compare copies trained
with and without the demo, measure fresh-public decision regret and false
feasibility, and check whether disclosure changes the takeover outcome. It has
not been run. Customer-demo utility has not been measured either. All acceptance
thresholds and publication choices are HUMAN_INPUT; similarity does not prove
IP infringement, and the owner's rights policy remains separate.
