## 2026-10-05 — OWNER-EV5-GPU-01: EV5 pods on the cheapest GPU that works, whatever the rate

**Authority.** The owner, directly in the Data Collection session on 2026-10-05:

> Find a GPU that works for this regardless of cost. Just pick the lowest price

The owner then switched the session's permission mode so that the tooling change could go ahead ("switched", "try again").

**Amends** OWNER-EV5-CAP-01's compute line ("RunPod A40 at no more than USD 0.49 per hour"). Nothing else in EV5's freeze changes.

## Why

The EV5 dispatch began at 16:14Z. For about 80 minutes RunPod either listed no A40 at or under USD 0.49/h, or the create call failed with HTTP 500. No pod was created and nothing was spent.

## Decision

1. **GPU list.** Pods may use any of these Secure-cloud GPUs on CUDA 13.0, cheapest available first:
   - A40;
   - L4;
   - RTX 3090;
   - RTX 4090;
   - RTX 6000 Ada;
   - L40S;
   - A100 SXM4 80 GB.

   **Rate ceiling.** USD 1.59/h per pod.

   **Excluded.** Blackwell parts, which the pinned JAX/CUDA image is not known to support.
2. **Campaign cap.** Amended in the campaign ledger (`cap_amended`, decision OWNER-EV5-GPU-01) from the start cap to the operator ceiling, a worst-case figure for every phase at the top rate. It never exceeds the account balance less the operator's floor. The figures stay in operator configuration (POD-LEDGER-PRIVATE-01).
3. **Tooling.** `pod_control` (operations branch `claude/ev5-ops-gpu`, cut from c9c27a63):
   - `CARBON_POD_GPUS` and `CARBON_POD_MAX_RATE` set the GPU list and rate ceiling. Unset, it is A40 at USD 0.49 as before.
   - `amend-cap` records an owner cap decision.
   - `--ship-only FILE` ships an explicit, hash-pinned file list in place of the plan's whole trees.

   Pods still fetch code at the pinned EV5 ref, c9c27a63, so the run record's code is what runs.

## Deviations found while dispatching (reported, not silent)

1. **The create request was too large.** The 500s came from the size of the create request: the frozen plans ship the whole `carbon/` tree, and its hash manifest had grown from 544 files (EV4) to 1017. Every create succeeded once the pods shipped the static import closure of the pod phases instead:
   - 410 modules;
   - their packages' data files;
   - `scripts/dev/exam_design`.

   That is 502 to 507 files, each hash-pinned at c9c27a63. The narrowed set was import-checked offline before any dispatch.
2. **The frozen panel plan was missing a file the phase reads.** `ev5.optimizer_spec()` reads `docs/development/evidence/sr-ev4-2026-10-02/sr2/results.json` to name the candidate rule. The first panel pod (A40, about 2 minutes) stopped on `FileNotFoundError` before producing any usable output, and was fetched and terminated. That file was added to the shipped list, and the panel was redispatched. This would have failed with the full `carbon/` tree too.

No code, plan, rule, cutoff or analysis changed. The pods run the pinned c9c27a63 code.
