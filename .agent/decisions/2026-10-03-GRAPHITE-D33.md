## 2026-10-03 — GRAPHITE-D33: the Graphite Constructor runs under the research loop's parallel-call rule

**Authority.** Owner approval, in session on 2026-10-03, relayed to the
executor by the coordinating session: apply the existing `PARALLEL_CALLS` rule
to the Graphite Constructor role, so that a turn with several tool calls runs
the first call and refuses the rest instead of ending the run with
`harness_error`. Use the existing policy object; invent no new policy and
change none of its limits. The owner's exact words are not in this record. The
rule itself is the owner decision of 28 September 2026
(`research_agent_policy.PARALLEL_CALLS`). Stating the rule in the
Constructor's prompt and the dry run's several-call turn (items 3 and 4) are
engineering choices within GRAPHITE-01's delegated authority.

Ticket: `.agent/tickets/GRAPHITE-01_in_house_testing_agent.md`.

**The defect.** Graphite phase 3 live session 1 (run
`graphite-913bf1889a6db2d1`, code at main `e8ebf13c`) failed after its first
model call.
- The Constructor's model (`deepseek-v4-flash-0731` through `engy-anthropic`)
  answered turn 1 with three tool calls: `get_challenge_info`,
  `get_interaction_manifest` and `get_mock_scaffold`, each with `{}`. The
  request had sent `parallel_tool_calls: false`, which reaches Engy as
  `disable_parallel_tool_use: true`.
- Graphite ran the loop with `parallel_calls=None`, the historical rule. The
  loop raised `ValueError("parallel tool output prohibited; retained and
  stopped")`, and the run ended `failure: {code: harness_error, type:
  ValueError}`.

**Decision.**
1. **The rule, by role.** `roles.PARALLEL_RULES = {RoleName.CONSTRUCTOR:
   PARALLEL_CALLS}`. Both places a Graphite session runs its epoch,
   `GraphiteProvider._epoch` and `Phase3Provider._epoch`, pass
   `parallel_calls=PARALLEL_RULES.get(role.name)` to
   `research_loop.run_epoch`. The policy object is the existing one,
   unchanged:
   - the first call runs;
   - every other call is answered with `PARALLEL_REFUSAL`, dispatches
     nothing and is journalled (`*-parallel-refusal.json`);
   - after `consecutive_limit` (3) consecutive turns with several calls, the
     session stops `STOPPED`, retained. That is a typed outcome, not a
     harness error;
   - the epoch plan records the rule.
2. **Every other role** keeps the loop's historical rule (`None`): such a turn
   stops the session. The owner's decision names the Constructor only.
3. **The Constructor is told the rule.** Its prompt states it in the words the
   battery agent gets from `operating_rules()`, with "session" in place of
   "epoch" (OWNER-BATTERY-V2-DISCLOSURE-01: tell the agent every operating
   rule before it can hit one). The sentence is built by
   `research_agent_policy.one_call_per_turn` from `PARALLEL_CALLS`, so the
   stated limit is the enforced one. `operating_rules()` is byte-identical.
4. **The dry run catches it before spend.** `phase3 run --dry-run` opens with
   live session 1's three-call turn and reports `refused_parallel_calls`,
   counted from the journal.

**Consequences.**
- The Constructor's prompt digest changes. A Constructor session opened under
  the old prompt refuses to resume (`role_changed`) before any model call.
  Live session 1 is already terminal (`failed`); the next session opens with
  the new prompt and rule.
- A refused call does not run, but its turn still spends one of the session's
  150 model calls (GRAPHITE-D26), as in the battery campaign.
- No grant, cap, permission profile, tool manifest, score or miner-path
  behaviour changes.

**`operation_id`, checked: no change needed.** The miner MCP door requires
`operation_id` (`^[A-Za-z0-9._:-]{16,114}$`).
- Graphite's bridge supplies it, outside the model's arguments:
  `miner_path.MinerPathTools.operation_id` makes `graphite-<session>-<tool
  identity>`, for example `graphite-913bf1889a6db2d1-epoch-1-tool-000`.
- The model-facing schemas of `get_challenge_info`, `get_interaction_manifest`
  and `get_mock_scaffold` have no properties. `{}` is the exact argument set
  the adapter accepts (`miner_mcp.standard._arguments`).
- `tests/service/test_graphite_miner_path.py` already sends
  `get_challenge_info` with `{}` through the real `ResearchToolAdapter`, and
  the battery service answers it.

**Alternatives rejected.**
- *The rule for every Graphite role.* The owner named the Constructor, and
  other roles' recorded sessions keep their meaning.
- *Resend the turn, or retry with a stronger instruction.* It spends calls and
  changes the loop's semantics; the existing rule already handles the turn.
- *A Graphite-specific policy or limit.* The owner asked for the existing one;
  all of Carbon's agents keep one rule.
- *A field on `GraphiteRole`.* It would change every role's recorded shape
  for a rule one role uses.

**Reversal.** Remove the Constructor's entry from `roles.PARALLEL_RULES` and
the prompt sentence. The tests below name the behaviour and fail if it
changes.

**Tests.**
- `tests/cpu/test_graphite_phase3.py`: live session 1's turn runs the first
  call and refuses two, journalled, and the session goes on; three such turns
  in a row stop the session typed; only the Constructor holds the rule and its
  prompt states the enforced limit; the dry run reports two refused calls.
- `tests/cpu/test_graphite_boundaries.py`: the same rule for a Constructor
  under `GraphiteProvider`; a Reader still stops (`harness_error`).
- Mutation cases `constructor_parallel_rule` in
  `tests/cpu/test_graphite_phase3_mutations.py` and
  `tests/cpu/test_graphite_mutations.py`: without the rule, the guarding test
  fails.

**Unchanged.** Graphite proposes; Carbon's verifier decides (invariants 7.9
and 7.10). No live session was run for this change and nothing was spent.
None of this is scientific, security or production qualification. No
human-reserved input remains.
