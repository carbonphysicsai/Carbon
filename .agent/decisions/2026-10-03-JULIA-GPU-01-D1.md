# 2026-10-03 — JULIA-GPU-01-D1: the pinned Julia depot carries CUDA.jl 6.2.2 on the CUDA 13.0 toolkit

**Authority.** OWNER-EXEC-APPROVALS-01 item 4 ("GPu Julia"). The toolkit
choice is an engineering decision delegated by the ticket
(`.agent/tickets/JULIA-GPU-01_cuda_julia_depot.md`), recorded here as the
ticket requires.

**Decision.**
1. **Package.** CUDA.jl 6.2.2 joins the `current` environment with
   `PRESERVE_ALL`.
   - It resolves against Julia 1.13.0 and against the GPUCompiler 1.23.0 and
     LLVM 9.13.1 that Enzyme already pins. No existing version or tree hash
     moves; 22 packages are added. No owner question about a separate
     environment or depot arises.
   - cuDNN is not added: nobody asked for GPU convolutions.
2. **Toolkit.** The toolkit is fixed at **CUDA 13.0**
   (`[CUDA_Runtime_jll] version = "13.0"`, `local = false`), and the bundled
   forward-compatible driver is disabled (`[CUDA_Driver_jll] compat = false`),
   in a committed `current/LocalPreferences.toml`. It is the toolkit the pinned
   Python GPU worker carries (`.devcontainer/accelerators/cuda13-py311.txt`,
   runtime 13.0.48), so one host floor serves both languages:
   - an NVIDIA driver supporting CUDA 13.0 (the 580 series or later);
   - Turing (sm_75) or newer, since CUDA 13 dropped Maxwell, Pascal and Volta.
3. **Extras.** Both JLLs are listed under `[extras]` in `current/Project.toml`.
   Julia reads a package's preferences only when the project names it. A
   rehearsal without the extras silently came out `cuda+none` and installed
   no toolkit. This is what `CUDA.set_runtime_version!` does; the manifest is
   unchanged by it.
4. **Depot identity.** `LocalPreferences.toml` is a depot input.
   - The lazy-artifact sweep leaves CUDA-tagged JLLs to their own selection
     hook, so exactly one toolkit is installed.
   - The build runs `CUDA.precompile_runtime()` and keeps only GPUCompiler's
     compiled scratch, 54 device runtimes (2.4 MB).
   - Bootstrap bytes are unchanged, so historical scopes keep their meaning.

**Measured (2026-10-03, WSL host with an RTX 3060 Laptop GPU, driver 13.0).**
- **Build.** Depot `sha256:52a6de6c…` (image `sha256:aa09e0ac…`) built cold in
  54 min.
- **Size.** The image is 25.37 GB against 21.09 GB before: **+4.28 GB**.
- **Offline, no GPU.** In the read-only, network-off sandbox, CUDA loads from
  cache in 3.2 s, finds its 13.0 runtime and compiler artifacts, and reports
  `functional() == false`. Both environments pass the composer's
  precompiled check: 73 and 79 packages.
- **With the GPU attached.** `functional()` is true and a kernel is correct.
  The first kernel takes 3.7 s, later ones 0.19 s.
- **Device runtime seeding.** Seeding the per-run depot with the precompiled
  device runtime changed the first kernel by about 0.1 s. Slice 2 may skip
  seeding; GPUCompiler reads that cache from the first depot only.

**Unchanged.**
- The validator stays on jax-cpu. Julia analysis stays
  `official_eligible: False` and `PUBLIC_MINER_AUTHORED_JULIA_NO_EVALUATOR`.
- GPU practice is speed only, never evidence.
- The reference-worker images and `reference_runtime/julia/Manifest.toml` are
  untouched.
- `run_julia` with `device: gpu` stays refused (`julia_gpu_unavailable`)
  until slice 2.
- Nothing is security-qualified (OWNER-EXEC-APPROVALS-01 item 3; AGENTS.md
  §13).
