## 2026-10-04 — GRAPHITE-D34: the Graphite Constructor's whole context window, a 600 s timeout, and phase 3 on engy-chat

**Authority.** Owner decisions of 2026-10-04, relayed to the executor by the
coordinating session:
- approving this fix: "approve the hold and fix";
- the input window: "yeah we need to allow for as much context as possible.
  whatever that value is, max it out";
- pre-approving the executor's recommendation on the reported charge and the
  timeout: "perfect. I approve what comes back".

The per-model values come from Engy's public model list, not from a choice.
The 600 s timeout and moving phase 3 to `engy-chat` are the executor's
recommendations, which the third quote approves. Placing the settings by role
and the dry run's report are engineering choices within GRAPHITE-01's
delegated authority.

Ticket: `.agent/tickets/GRAPHITE-01_in_house_testing_agent.md`.

**The defect.** Graphite phase 3 live session 2 (run
`graphite-d90a8ccfd603cf6a`, code at main `ff796899`, the Constructor on
`deepseek-v4-flash-0731` through `engy-anthropic`) ended after 2 model calls.
- Provider state `succeeded`; delivery `NO_IMPROVEMENT`; loop outcome
  `STOPPED`, code `context_ceiling`: "context admission ceiling; no history
  silently discarded". No compaction ran or was deferred.
- Turn 0 made 3 calls. Turn 1 made 5 `start_research_task` calls, which all
  ran; their results were about 69 KB together (the largest about 30 KB).
  Engy reported 7,055 input tokens on turn 0 and 10,607 on turn 1.
- Cause: `GraphiteProvider._selection` called `select` with no `settings`, so
  every Graphite session ran at `model_provider.DEFAULT_SETTINGS`: 65,536
  input tokens, so an admission ceiling of 65,536 − 4,096
  (`CONTEXT_RESERVE_TOKENS`) = 61,440. The loop bounds the next request at
  the reported tokens plus the bytes appended since
  (`research_agent.input_token_bound`): 10,607 + about 69,000 > 61,440, so the
  session stopped before turn 2. Compaction could not help: it is due only
  once the conversation holds more than `keep_last_turns` (6) turns.
- Neither the campaign nor the runner profile can set these values; only code
  can.

**Second finding: no reported charge on `engy-anthropic`.** In live session 2
every call's settlement reads "provider charge not reported; full reservation
retained", with `charged_micro` null.
- The Messages translation reads `x_engy` from the reply body
  (`model_provider.messages_response` and `provider_report`), exactly as the
  Chat Completions translation does. Nothing is lost in parsing.
- Carbon measured on 2026-09-27 that Engy's Messages endpoint returns no
  `x_engy` block at all (`docs/development/BATTERY_AGENT_CAMPAIGN_V2_RESULTS_TIERS_0_1.md`,
  finding 7; `scripts/dev/battery_campaign_v2/tier0.py`). The owner then moved
  battery tier 2 to `engy-chat` for that reason (amendment 1, 2026-09-28).
  Phase-2 triage on `engy-anthropic` saw the same (OWNER-GRAPHITE-02
  amendment).
- Engy's Chat Completions endpoint does report it: battery tiers 0 and 1, and
  the Launchpad smoke campaign on `engy-chat`, settled every call from
  `x_engy.charged_micro`.
- No recorded fixture or document shows the charge anywhere else in a
  Messages reply (a header, say), so no parsing fix is possible without
  inventing one.

**Decision.**
1. **The Constructor's input window is its model's whole context.**
   `roles.MODEL_SETTINGS` maps a role to its model settings for each model on
   the ladder; only the Constructor is named. For each model,
   `max_input_tokens` is min(Engy's published `context_length`,
   1,048,576), where 1,048,576 is the most `select` accepts. Engy's public
   list (`https://api.engy.ai/v1/models`, read without a key on 2026-10-04)
   gives `context_length` equal to `max_model_len`:

   | Rung | Model | Context | `max_input_tokens` | Admission ceiling |
   |---|---|---|---|---|
   | 0 | `deepseek-v4-flash-0731` | 1,048,576 | 1,048,576 | 1,044,480 |
   | 1 | `qwen3.8-27b` | 1,001,536 | 1,001,536 | 997,440 |
   | 2 | `glm-5.3-flash` | 262,144 | 262,144 | 258,048 |
   | 3 | `glm-5.2` | 262,144 | 262,144 | 258,048 |
   | 4 | `kimi-k3` | 1,113,088 | 1,048,576 | 1,044,480 |

   The table is `roles.ENGY_CONTEXT_TOKENS`, with its source and date. A
   model it does not list has no recorded context: a Constructor session on
   it is refused (`model_context_not_recorded`) before anything is opened.
   Escalation selects again for each rung, so each rung gets its own value.
2. **Output and reasoning are unchanged.** `max_output_tokens` stays 2,048
   and `reasoning_effort` stays `low` (`DEFAULT_SETTINGS`). The loop admits a
   request only under `max_input_tokens − 4,096`, and its bound never
   undercounts, so a request's input plus the 2,048 output tokens stays at
   least 2,048 tokens inside the model's `max_model_len`.
3. **A 600 s provider timeout** for the Constructor, up from 120 s. It is
   `select`'s maximum and the level planner's value. A request near a million
   tokens may take minutes to prefill, and a call that times out has an
   unknown outcome: it keeps its full reservation and stops the session
   `RECONCILIATION_REQUIRED`. The cost: a model call is admitted only when
   600 s fit the run's remaining time, and a call that hangs holds the session
   up to its 610 s hard deadline (GRAPHITE-D27).
4. **Phase 3 runs on `engy-chat`.** `Phase3Provider` opens its sessions on
   `phase3.ADAPTER = "engy-chat"`, so each call settles from Engy's reported
   charge. The rest of the session is the same: the Constructor's prompt,
   tools, `PARALLEL_CALLS_V2` and the miner path. The Chat Completions
   translation carries a turn's several tool calls as one assistant message,
   answers each with its own `tool` message, and sends
   `parallel_tool_calls: true`. Two differences, both from the protocol: no
   reasoning setting is sent (Chat Completions has no portable one), and no
   thinking block is carried back. `GraphiteProvider` itself keeps
   `engy-anthropic`; only phase 3 runs live sessions.
5. **Prospective.** A session records its selection in `session-open.json`
   (`opened["model"]`). `run` rebuilds it from the record
   (`selection_from_record`), which re-validates the recorded adapter, model
   and settings through `select` and must reproduce the record exactly; then
   `_verify` compares it with the record. Neither reads `MODEL_SETTINGS` or
   the provider's adapter. The role's prompt and manifest, the brief, the
   literature, the grant record, the caps and the session-limits block do not
   change, so `_verify` and `_expected_limits` compare what they compared
   before. A session opened before this change therefore resumes on
   `engy-anthropic` at 65,536 tokens and 120 s, and replays byte-identically.
   It is neither refused nor changed.
6. **The dry run shows it before spend.** `phase3 run --dry-run` reports the
   session's adapter, model, `max_input_tokens`, admission ceiling, output
   cap, timeout and per-call reservation, read from its session record.

**Roles checked.** All six.
- Only the Constructor runs live sessions through `GraphiteProvider`, in
  phase 3. `phase3.session_brief` is the only `SessionBrief` built outside
  tests.
- The Planner, the Optimizer researcher and the Reader run their live work as
  closed tasks with their own settings: `level_planner.SETTINGS` (196,608),
  `optimizer_research.SETTINGS` (32,768) and `triage.TRIAGE_SETTINGS`
  (16,384).
- The Attacker and the Writer have no live session path yet.
- So only the Constructor is named. Another role is added to
  `MODEL_SETTINGS` when it gets live sessions.

**Consequences.**
- **Each call reserves more.** At full reservation the run's 1.95 token share
  holds 41 calls on `deepseek-v4-flash-0731` (622 before), 42 on
  `qwen3.8-27b`, 53 on `glm-5.3-flash` and 10 on `glm-5.2` (40 before). One
  `kimi-k3` call reserves USD 2.0647, more than the token share, so a session
  on that rung is refused, typed, before its first call. Under this grant the
  Constructor cannot reach that rung: it escalates one rung per stalled
  session, and the grant permits 3 runs. The figures and their arithmetic
  are in `docs/development/graphite/grants/README.md`.
- **On `engy-chat` each call settles at its reported charge**, so the token
  share holds as many calls as the charges allow, while each call in flight
  still needs its full reservation free.
- **Time.** `max_runtime_s` stays 39,600. A model call needs 600 s left
  instead of 120 s, so the run's last ten minutes admit no call. The elapsed
  limit binds the number of calls only when calls are slow.
- The status line the agent sees before each turn states the larger per-call
  hold ("each model call holds up to USD 0.0474" on the first rung).
- No grant value, cap, permission profile, tool manifest, prompt, score or
  miner-path behaviour changes. `DEFAULT_SETTINGS`, the research tools, result
  sizes and the compaction rule are unchanged.

**Alternatives rejected.**
- *196,608 input tokens on every rung* (the level planner's value; the
  executor's first recommendation). Superseded by "max it out".
- *One value for every rung* (262,144, the smallest context). It leaves three
  quarters of the first rung's window unused.
- *Read the charge from a Messages header.* No record shows Engy sending one,
  so that would be invented. If Engy adds one, a parser with a recorded
  fixture can follow.
- *Stay on `engy-anthropic`.* Every call would keep its full reservation: 41
  calls on the first rung, 10 on `glm-5.2`.
- *A larger token share.* That is a grant value: the owner's.
- *Change the compaction rule.* It does not reach the first turns, and the
  rule is shared.

**Reversal.** Remove the Constructor's entry from `roles.MODEL_SETTINGS`, and
set `phase3.ADAPTER` back to `engy-anthropic`. Sessions opened in between
keep their recorded selections. The tests below name the behaviour and fail
if it changes.
