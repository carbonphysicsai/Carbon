## 2026-10-03 — LP-PROD-G: the battery validator runs as a supervised service behind its intake

**Authority.** OWNER-LAUNCHPAD-PROD-01: the owner, in chat on 2026-10-03,
approved the Launchpad production work list ("approve. you launch this
now"), whose slice G is a real submission endpoint and validation service on
the validator-pinned images. Engineering decisions within that slice,
recorded by the executor. Exposure stays under OWNER-INTAKE-EXPOSURE-01; the
carry-over under OWNER-BATTERY-CARRYOVER-01.

**Decision.**

1. **The service is two processes over one deployment.** The intake
   (`python -m carbon.battery.intake serve`) and the validator daemon
   (`python -m carbon.battery.operate run --every SECONDS`, a new flag: one
   `run` per period, SIGTERM ends it after the pass in flight). Both already
   serialise on the deployment's writer lock, so neither needs the other.
   `scripts/dev/battery_validator_service` adds a service configuration
   (`carbon.battery.validator-service.v1`), `preflight`, `parity`, `status`,
   `backup`, `restore`, `supervise` and `units` (`systemd --user`). A child
   that exits 2 refused its configuration and is never restarted; other
   exits restart with a doubling backoff (1 s to 60 s) and stop after 5
   restarts in 10 minutes. These periods and limits are engineering values.
2. **The preflight fails closed, by named code, and reports every check at
   once.** Owner-only configurations; the pinned worker images present by
   digest and doctor-eligible; the stored binding equal to what a start
   binds from this checkout (`deployment_not_upgraded` names the fields);
   image and contract parity; and, only for a non-loopback bind, the
   recorded exposure, an existing certificate, an owner-only key that loads,
   and the isolated carrier. A `direct` deployment is accepted only with
   `allow_direct_backend` and never beyond loopback.
3. **Parity is identity equality.** Every image the deployment scores with
   needs the manifest miners practise with under the same key
   (`practice_images.image_manifest`, `.torch_image_manifest`), and every
   identity field must match (`parity_image_differs`). The bound contract
   must be this checkout's registered battery contract
   (`parity_contract_differs`). Nothing here picks which image is right.
4. **`operate upgrade` binds what a start binds** (`operate.serving_identities`).
   A read-only build runs the in-process backend, and `upgrade` bound that
   backend's identity, so a carrier deployment's next start refused
   `identities_changed` and a second `upgrade` changed nothing. It now binds
   the carrier identity from the pinned manifests; an affected deployment is
   repaired by one `upgrade` (`changed: ["backend"]`). Recorded here because
   it changes the only path that rebinds a deployment.
5. **An admission refusal that is not a verdict is received again on
   resend** (`intake.RECEIVED_AGAIN`): the window, an undated receipt, a
   missing commitment or commitment reader, an unserved backend. Before,
   only the window was, and the others held a recipe's one submission id
   refused for good.
6. **The Launchpad's intake path consumes an epoch only with a verdict.**
   A submission the worker refused came back as the epoch's feedback with
   state REFUSED. Now every non-verdict is an `OperationRefused` with a
   closed code (`intake_code`), classified `QUEUED`, `UNAVAILABLE` or
   `REFUSED` (`campaign.intake_outcome`) and explained
   (`intake_client.explain`). A refusal named in item 5, or `not_found` for
   the epoch's recorded submission, resends the same candidate once per
   call; a window refusal is resent only once the intake's chain has reached
   the window. A candidate recorded against another intake is refused
   (`intake_changed_since_submission`).
7. **The TLS handshake leaves the accept loop.** The listening socket was
   wrapped with the default `do_handshake_on_connect`, so every handshake
   ran in `accept`, in the single serving thread, with no timeout: one client
   that connected and sent nothing stopped the intake for everyone. Each
   handshake now runs in its connection's thread under the 10 s socket
   timeout. A failed connection is logged by exception type, not by the
   base class's peer address and trace.
8. **Backups are root, journal and state together**, copied under the
   writer lock (SQLite through its backup API), with the intake's inbox and
   transport journal, a manifest of digests and the root's public
   commitment. A restore verifies first and never overwrites.
9. **Logs are JSON lines of events, counts and exception types**, never a
   peer, hotkey, path, request, case or seed.

**Unchanged.** The default bind is loopback; exposing a host, the public
host, DNS name, TLS certificate and firewall stay the owner's
(`docs/development/BATTERY_VALIDATOR_SERVICE_RUNBOOK.md` §5). No scientific
value, threshold, gate or tolerance changed. Carbon holds no hotkey; nothing
writes to a chain or sets weights; scores stay DEVELOPMENT evidence. Tested
on loopback with throwaway deployments only, never the operator's. Not a
security audit, and nothing here is SECURITY_QUALIFIED (AGENTS.md §13).
