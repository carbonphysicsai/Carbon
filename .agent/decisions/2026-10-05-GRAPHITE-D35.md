## 2026-10-05 — GRAPHITE-D35: the phase-4 Attacker's whole context window

**Authority.** Owner decision of 2026-10-05, given in chat to the Test Lead
and relayed by the Test Lead to the Test Engineer. Asked whether the Attacker
should get its model's full context as the Constructor did under GRAPHITE-D34
("max it out"), the owner answered:

> "yes for attacker budget"

GRAPHITE-D34 (`.agent/decisions/2026-10-04-GRAPHITE-D34.md`) is the
precedent: the same owner rule, applied to the Constructor on 2026-10-04.
The per-model values are Engy's published context, already recorded by D34,
not a choice. Reusing D34's mechanism, the dry run's and the pre-live gate's
report, and the tests are engineering choices within GRAPHITE-01's delegated
authority.

Ticket: `.agent/tickets/GRAPHITE-01_in_house_testing_agent.md`.

**Before.** D34 named only the Constructor in `roles.MODEL_SETTINGS`, because
the Attacker had no live session path then. Phase 4 (`phase4.AttackerProvider`,
#504's `Phase3Provider`) has one now, and its sessions opened at
`model_provider.DEFAULT_SETTINGS`: 65,536 input tokens (an admission ceiling
of 61,440), a 120 s timeout. They already ran on `engy-chat` (D34 §4), so each
call settles from Engy's reported charge.

**Decision.**
1. **The Attacker's input window is its model's whole context.** D34's
   mechanism is reused, not copied: `roles.WHOLE_CONTEXT_ROLES` names the
   Constructor and the Attacker, and `roles.MODEL_SETTINGS` gives each the
   same per-model table built by `_whole_context` from
   `roles.ENGY_CONTEXT_TOKENS` (Engy's public list, observed 2026-10-04). On
   its starting model, `glm-5.2`, an Attacker session opens with 262,144 input
   tokens (admission ceiling 258,048) and the 600 s timeout on `engy-chat`.
   Output stays 2,048 tokens and reasoning `low`. Each rung gets its own
   window. A model the table does not list is refused
   (`model_context_not_recorded`) before anything opens.
2. **Every other role is unchanged.** The Planner, the Optimizer researcher,
   the Reader and the Writer are not named and keep `DEFAULT_SETTINGS`; the
   Constructor's table is D34's.
3. **Prospective (invariant 10).** A session's selection is frozen in its
   `session-open.json`; `run` rebuilds it from the record
   (`selection_from_record`) and `_verify` compares it, reading neither
   `MODEL_SETTINGS` nor the provider's adapter. An Attacker session opened
   before this change resumes at 65,536 tokens and 120 s and replays
   byte-identically; it is neither refused nor changed.
4. **The evidence shows it before spend.** `phase4 run --dry-run` (under
   `dry_run.attacker_model`) and `phase4 prelive` (top-level
   `attacker_model`) print the session's recorded adapter, model, input
   window, admission ceiling, output cap, timeout and per-call reservation,
   with the run's token allowance and how many full reservations it holds
   (`phase4.attacker_model`, built on phase 3's `model_window`).

**Spend stays capped.** No grant value changes. GRAPHITE-GRANT-PHASE4's run
cost (USD 3.41) and the Attacker's split (`phase4.attacker_budget`: six verify
pods, USD 1.48, and a token allowance of USD 1.93, the session's money cap)
bind as before; the battery and `chip-cold-plate` Level 0 budgets are the
same. Each call's reservation is
`max_input_tokens × input price + 2,048 × output price`:

| Model | Reservation before (65,536) | At its whole window | Full reservations in USD 1.93 |
|---|---|---|---|
| `deepseek-v4-flash-0731` | 0.00313344 | 0.04737024 | 40 (615 before) |
| `qwen3.8-27b` | 0.00360448 | 0.04572448 | 42 (535 before) |
| `glm-5.3-flash` | 0.00976896 | 0.03631104 | 53 (197 before) |
| `glm-5.2` (start) | 0.04763648 | 0.18132992 | 10 (40 before) |
| `kimi-k3` | 0.1477632 | 2.0646912 | 0 (13 before) |

- On `glm-5.2`, the Attacker's starting model, one call's reservation fits
  the token allowance ten times. On `engy-chat` each call settles at its
  reported charge, so the allowance holds as many calls as the charges allow,
  while each call in flight still needs its full reservation free.
- One `kimi-k3` call reserves more than the allowance, so an Attacker session
  on that rung stops `run_cap_reached` (`provider_nanodollars`), typed, before
  its first call: nothing sent, nothing spent. The Attacker reaches that rung
  only through a recorded `NO_WELL_FORMED_ATTEMPT` escalation from `glm-5.2`,
  and phase 4 records none itself. This is reported, not fixed: raising the
  token share is a grant value, the owner's.
- **Time.** `max_runtime_s` stays 15,600. A model call is admitted only when
  600 s fit the run's remaining time (D34), so the run's last ten minutes
  admit no call; a call that hangs holds the session up to its 610 s hard
  deadline (GRAPHITE-D27).

**Alternatives rejected.**
- *A separate Attacker table or a phase-4 override of `_selection`.* A copy of
  D34's mechanism, which could drift from it.
- *Keep the Attacker at `DEFAULT_SETTINGS`.* Superseded by the owner's answer.
- *A larger token share so `kimi-k3` fits.* A grant value: the owner's.

**Reversal.** Remove `RoleName.ATTACKER` from `roles.WHOLE_CONTEXT_ROLES`.
Sessions opened in between keep their recorded selections.

**Tests.** `tests/cpu/test_graphite_phase4_model.py`:
- an Attacker session opens on `glm-5.2` with 262,144 input tokens and the
  600 s timeout on `engy-chat`, not `DEFAULT_SETTINGS`; every rung gets its
  own window;
- a model with no recorded context is refused before anything opens;
- every other role keeps `DEFAULT_SETTINGS`, and only the Constructor and the
  Attacker are named;
- an Attacker session recorded at `DEFAULT_SETTINGS` resumes from every crash
  point with its recorded settings and replays byte-identically;
- at the whole window the token allowance still binds: with no charge
  reported, a `glm-5.2` session makes exactly ten calls and stops
  `run_cap_reached`; a `kimi-k3` session stops before its first call;
- the dry run and `prelive` print the `attacker_model` block;
- mutation cases, one per guard (`attacker_whole_context`,
  `unlisted_model_refused`, `other_roles_unchanged`,
  `resume_keeps_recorded_settings`, `token_allowance_binds`,
  `prelive_block_from_the_record`): without the protection, the guarding test
  fails.

`tests/cpu/test_graphite_boundaries.py` now expects exactly the Constructor
and the Attacker in `MODEL_SETTINGS`, with the same table.

**Unchanged.** Graphite proposes; Carbon's verifier decides (invariants 7.9
and 7.10). No live session was run for this change and nothing was spent.
None of this is scientific, security or production qualification. No
human-reserved input remains.
