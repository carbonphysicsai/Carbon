## 2026-10-03 — JULIA-GPU-01-D2: `run_julia` on the miner's own GPU, in the same miner lane

**Authority.** OWNER-EXEC-APPROVALS-01 item 4 ("GPu Julia"). These are
engineering choices delegated by the ticket
(`.agent/tickets/JULIA-GPU-01_cuda_julia_depot.md`, slice 2). They build on
JULIA-GPU-01-D1, the CUDA 13.0 depot.

**Decision.**
1. **This machine's GPU.** `run_julia` with `device: gpu` runs in the miner
   lane `run_python` uses: the isolated container, one GPU by UUID, the same
   device lease and shared-slot check. The image is the campaign's composed
   Julia image, not the Python GPU worker.
   - Only an environment in `CUDA_ENVIRONMENTS` (`current`) may run there.
     `pde` has no CUDA and is refused before dispatch:
     `julia_gpu_environment_without_cuda`.
2. **Host check.** Before dispatch the carrier:
   - verifies the composed image and its depot, as every Julia run is
     verified;
   - checks the NVIDIA container runtime and the miner lane's required host
     findings;
   - confirms the installed device record has not changed.

   The Python GPU worker's lock and labels are not required, because a Julia
   image does not carry them.
3. **Remote GPU stays refused, under its own code.** A remote GPU runs
   `run_python` only (`remote_julia_gpu_unavailable`). The remote route is
   bound to the one pinned Python GPU worker. A lane now lists the actions it
   runs (`actions`), and a local lane also lists the Julia environments it
   runs on GPU (`julia_environments`).
4. **No device-runtime seeding.** GPUCompiler reads its device-runtime cache
   from the first depot only, which is the per-run writable one. Measured on
   2026-10-03 with an RTX 3060 Laptop GPU, seeding it from the image's
   precompiled copy changed the first kernel by about 0.1 s (3.6 s against
   3.7 s). The bootstrap stays byte-identical, and historical scopes keep
   their meaning.
5. **No new worker profile.** The ticket proposed a Julia CUDA profile in
   `research_carrier._worker_profile`. That profile serves only Carbon's own
   non-miner lane. A miner's code cell, Julia included, runs in the miner lane
   (`_run_miner_lane`), which attaches the device itself. A profile would
   describe a run that never happens.

**Unchanged.**
- The validator stays on jax-cpu. Julia analysis stays
  `official_eligible: False`.
- GPU practice and the GPU code cell are speed only, never evidence.
- The GPU code cell stays unqualified for security (OWNER-EXEC-APPROVALS-01
  item 3; AGENTS.md §13).
- A real kernel run through the lane is slice 3.
