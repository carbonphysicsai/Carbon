## 2026-10-04 — LP-PROD-FIX-01: a retained candidate waits READY, and new Graphite plans read a workspace "null" as JSON null

**Authority.** OWNER-LAUNCHPAD-PROD-01 (the Launchpad production work list).
The owner approved this fix in chat on 2026-10-04: "Yes, small PR now".
Engineering decisions within that approval, recorded by the executor. No
scientific value, threshold, gate, tolerance or economic parameter changes.

**Found.** Launchpad smoke run 382c4276, on the merged miner front end
(lessons entry `2026-10-04-retained-candidate-and-null-string`).

### D1. A campaign holding a retained candidate waits for its miner

**Observed.** A Graphite or Carbon-agent campaign whose submit was refused
`evaluation_unavailable` (`research_campaign.submit_or_retain` keeps the
frozen candidate and returns the code) settled INTERRUPTED with an empty
`interruptions.jsonl`. Opening the Tools tab left it RECONCILING, and a
restart settled it INTERRUPTED again, `campaign_interrupted` overwriting the
`evaluation_unavailable` refusal. Cause: every door that settles a campaign
asked only "is the agent `none`?" when deciding READY.

**Decision.**

1. **One rule:** `research_campaign.waits_for_its_miner(root, manifest=None)`.
   A prepared, unfinished campaign waits for its miner when it has no agent,
   or when it holds a **retained candidate**: the open committed final epoch
   (the first with no `permitted-final-feedback.json`) has its
   `selected-recipe.json` (`retained_candidate`). These are the files
   `freeze_refusal`, `submit_frozen` and the projection's
   `frozen_awaiting_submission` already read; the agent's SELECT writes the
   same `epoch-N/selected-recipe.json` for Carbon's agent and for Graphite's
   Constructor. No frozen manifest, or `campaign-complete.json`, is False.
2. **Every settling door asks it:** the run's own settle (`RunnerAdapter._run`),
   recovery after a restart (`_recover_one`), an idle settle (pause, stop,
   Reconcile: `_settle_if_idle`) and a detach (`standard_cli._waits_for_its_miner`,
   with the attachment's manifest). A pause or stop asked meanwhile still
   wins, as before.
3. **A run that raised keeps its interruption.** In `_run`, the retained
   rule applies only when the run returned; after an exception only the
   agent-less rule applies, as before, so the run stays INTERRUPTED and
   `record_interruption` keeps its line. The retained refusal itself is
   unchanged: `last_refusal` is `{code: evaluation_unavailable, operation:
   submit, next_action}`, and nothing is recorded as an interruption.
4. **Resume stays the way to submit again.** A READY agent campaign is
   resumed by the miner (the campaign page enables resume in READY; the MCP
   door's `carbon_resume` takes it); its run replays the epoch from its
   journal and resubmits the retained candidate, as before from INTERRUPTED.

### D2. A workspace strategy_json "null" is JSON null under a new frozen rule

**Observed.** Graphite's Planner sent `strategy_json` as the string `"null"`
on `kind=workspace`, and was refused `workspace_recipe_forbidden`; it had
the "JSON null, not the string" correction three ways and never adapted.

**Decision.**

1. **A new rule, frozen with the plan, separate from the tools rule:**
   `research_tools.ARGUMENT_NORMALISATION =
   "carbon.autoresearch.argument-normalisation.v1"`, under the plan key
   `argument_normalisation` (`frozen_argument_normalisation`,
   `campaign_argument_normalisation`). Kept apart from
   `research-tools.v2` so the tools and descriptions a campaign is offered
   stay byte for byte what it froze (Graphite's roles digest them). An
   unknown rule is refused, never read as none.
2. **What it normalises:** only `start_research_task` with `kind=workspace`
   and `strategy_json == "null"`, read as JSON null before the request is
   checked (`normalised_task_arguments`). The request built is byte for byte
   the one JSON null builds; what was sent is unchanged and is what the
   ledger binds and journals. `kind=practice` still refuses `"null"` (it
   needs a recipe). A workspace `arguments_json` is required, so null is
   never its value there and `"null"` is not normalised. Precedent:
   `research_loop.tool_arguments` reads `"null"` arguments of a no-argument
   tool as none.
3. **Who freezes it:** new Graphite plans (`battery.campaign.graphite_plan`),
   the plans new launches freeze. The autonomous plan is left as it was: no
   new launch freezes it (`autonomous_agent_replaced`), and its frozen digest
   is pinned (`test_battery_graphite_plan`).
4. **Campaigns frozen before it** name no rule, refuse `"null"` exactly as
   before (`workspace_recipe_forbidden` on `strategy_json`, the same
   correction text) and replay and continue unchanged.

**Unchanged.** No scientific value, gate, threshold or tolerance; no
economic parameter; nothing reaches a chain. No public interface field is
added or removed; one internal plan key is added prospectively for new
Graphite plans. This is engineering evidence, not a security audit.
