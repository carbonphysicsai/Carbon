## 2026-10-03 — LP-PROD-D: research tools as the model experiences them

**Authority.** Delegated engineering decisions (executor), within
OWNER-LAUNCHPAD-PROD-01: the owner's 2026-10-03 instruction to make the miner
front end zero-friction, production-level and state of the art, and the
owner's approval of the work list in chat on 2026-10-03 ("approve. you launch
this now"). Nothing here changes a scientific value, threshold, gate or
tolerance, live economics, a default spend, a chain write or weight, an
authority boundary or the security posture. Every result stays DEVELOPMENT
and MINER_SELF_REPORTED where it was.

**Why it is needed.** A workspace request with a bad *value* (a material name
outside the list, a stale `expected_digest`, a missing file, a run without a
wall allowance under a time budget, a design with an extra key) passed the
field check, started a task and ended FAILED_INFRA. The agent saw no reason:
the model's view drops the terminal receipt. Run results returned only
digests, so the agent could not see its own program's output or traceback.
Battery's roadmap and capability requests read Burgers' registry. The battery
discovery text described tools the agent does not have and examples that
`check_design` refuses.

**Decisions.**

1. **One value check, read before dispatch and at execution.**
   `research_tasks.check_workspace_request` is the one rule. The request path
   (`ResearchMinerTools._check_values`) reads it before anything is reserved,
   so a refused value starts no task, charges no research-trial slot and
   returns REJECTED_BEFORE_DISPATCH with a closed `correction_code`, the
   registered `field` and the fix. The executor reads it again before it
   acts. A request that reaches it anyway (a raw protocol client, or a
   workspace changed in between) completes as SUCCEEDED with
   `outcome: REQUEST_REFUSED` and the same three fields, `nothing_ran: true`,
   `trial_charged: false`. That is never FAILED_INFRA: the requester's value
   is not an infrastructure failure, the precedent `MINER_PROGRAM_FAILED`
   set. The historical exception text is kept, so a caller that only knew
   ValueError reads what it always read.
   - Codes added to `research_tools.TASK_CORRECTIONS`: public material, read
     range, workspace name, missing file, write content, expected-digest
     conflict (the correction explains what `expected_digest` is), notebook
     kind and reserved body, capability request object, missing and
     unexpected fields, reason, text bound and unknown id, the three
     `check_design` shapes, run hypothesis, source, files, seconds and
     required seconds, Julia environment, `backend_not_served`, unknown
     workspace action, oversized arguments, and the tool-level codes in
     decision 6.
   - Checks that read state (a file exists, a write's expected digest, the
     compute-time budget) are skipped when this operation id already started
     a task (`InMemoryResearchTaskProvider.started_task`, a trusted lookup).
     A resend then returns that task, and is never refused for a guard its
     own run moved.
   - The audit said `lifecycle.py` runs such a task three times. That holds
     only for the in-memory fixture provider. The real
     `DurableResearchTaskProvider` wraps the executor in `_NoRetry`, so the
     task failed once, without a reason. The retry policy is unchanged; the
     value never reaches it now.
2. **The program's output is in its result.** Each run result (CPU, Julia,
   local GPU, remote GPU) carries `program_output`. It holds the last 4096
   bytes of stdout and of stderr (`research_carrier.OUTPUT_TAIL_BYTES`). On a
   nonzero exit it also holds the traceback's tail, from its start, with its
   own last 4096 bytes kept if it is longer. This is an engineering bound on
   what reaches a model's context per call, not a limit on the program: the
   kept 64 KiB stay in the operation folder (RSURF-D21). Bytes that are not
   UTF-8 become U+FFFD.
   - `read_file` reads up to 65536 bytes per call (was 4096).
   - Text is also returned as `content_utf8`, null when the slice is not
     UTF-8. `content_base64` is kept for the Control Center page.
   - Both encodings, escaped at worst, stay well inside the 1 MiB public
     result bound.
3. **Each Challenge's own registry.** The executor names its Challenge
   (`PublicResearchExecutor.challenge`). Battery's composition sets it;
   omitted, it is Burgers', as before.
   - Capability requests, the roadmap and demand read that Challenge's
     registry.
   - Burgers' roadmap is unchanged byte for byte. Another Challenge's names
     itself.
   - A check-design verdict counts as demand only for its own Challenge.
   - A verdict for an unknown Challenge records no ids. Before, it raised
     inside the executor.
4. **A versioned tools rule; the historical tools stay byte-identical.**
   `research_tools.TOOLS` is unchanged and its digest is pinned in a test.
   Graphite's roles digest it, and frozen epoch plans record it.
   - `TOOLS_RULE` (`carbon.autoresearch.research-tools.v2`) has the same
     operations and schemas, with descriptions that say:
     - what each action takes and returns;
     - that `arguments_json` is an encoded string;
     - what `expected_digest` is;
     - the `device: cpu|gpu` choice;
     - that a run or a practice spends one research-trial slot, `run_julia`
       included;
     - that files written to `../output` (`/scratch/output`) are exported;
     - what `program_output` holds;
     - what a refusal means.
   - A campaign freezes the rule in its run plan (`provider.research_tools`).
     `tools_for_sdk` reads it from the campaign's frozen manifest. Without
     it, the historical tools are offered. A rule the code does not know is
     refused, never read as the historical one.
   - Freezing the rule in battery's `provider_plan` is slice A's change.
     This slice does not own that function.
5. **The battery agent's research environment, under the same rule.** A
   campaign that froze the rule sees `research_environment` in its first
   observation:
   - whether its runtime has a GPU lane for code cells, and which;
   - the backends its practice serves on this host;
   - whether authored Julia is offered.

   A practice whose recipe names an unserved backend is refused before
   dispatch with `backend_not_served`, listing the served backends
   (`BatteryPractice.backend_refusal`).
6. **Refusals name their tool and field.**
   - A wrong field set, an unknown tool, a JSON field that is not one object,
     a bad task id, an out-of-range integer, an unbounded hypothesis and an
     unknown action each get a registered code and field.
   - The correction text names the tool, never the requester's own text.
   - Corrections may list Carbon-written choices.
   - `research_tools.registered_correction` lets a door that forwards a
     refusal verify it is registered text.
   - `inspect_prior_alignment` is journalled as a refusal, not a capability
     request, so the demand stream holds only what the agent asked for.
7. **The compiler is not changed.** The domain specification
   (`Design_Specs/Candidate_Assembly_and_Strategy_Compiler_Contract.md`
   §10.4) fixes the compiler's codes and forbids dynamic diagnostics, and
   `strategy_limits` already names the exceeded capture limit at the
   research surface. `check_design` returns it as `limits_exceeded`, and the
   v2 description says so. Classified NO_CONFLICT; no owner input needed.
8. **The battery discovery document.**
   - `arguments_json` is shown as an encoded string.
   - `validate` points at `check_design`.
   - Freezing and submitting are named as the campaign's own steps, not
     research tools.
   - Progress text matches a start call that returns once its task has
     finished.
   - It states which backends practice serves.
   - Examples are designs as they stand (`{strategy}`), with their admission
     verdicts beside them in `examples_admission`. Readers of
     `examples[i]["strategy"]` are unchanged.

   This is a live public document, not a frozen record. A campaign is pinned
   to its exact accepted implementation revision, which `check_attached`
   compares on every attach. So no epoch plan frozen under the old text is
   ever rebuilt with the new one.

**Tests.** `tests/cpu/test_lp_prod_research_tools.py` (new). Updated, each
for a deliberate change stated in its own text:
- `test_cw1_research_tools.py`: the specimen names a wall allowance, and
  the shared-check assertion.
- `test_cw1_research_tasks.py`, `test_capability_demand.py` and
  `test_julia_research.py`: REQUEST_REFUSED replaces FAILED_INFRA for a
  refused value.
- `test_challenge_registry.py`: the examples' shape.
