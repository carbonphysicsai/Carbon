# CHALLENGE-AI-COOLING-VALIDATOR-08 — Interface-v1 adapter decisions

**Date:** 2026-10-05

**Authority:** delegated engineering choices under frozen VALIDATOR-01
Interface v1 and the already registered Cooling DEVELOPMENT contracts. This
record exercises no scientific, security, spend, qualification, customer,
production or LIVE authority.

## Decision

Cooling's first general-validator adapter evaluates only the exact pinned
public PRACTICE set. It reuses the existing Level-0 compiler, deterministic
KRR reconstruction, public TRAIN scales, prediction gates and aggregate. The
batch becomes usable only after the operator prepares it, ingests records that
exactly match the pinned artifact and explicitly opens the pool.

Miner disclosure is limited to the outcome state, score, eligibility and
descriptive case counts. Per-case inputs, references, predictions, gate rows,
recipe details and full identities stay on the operator surface.

The role `cooling-graphite-confirmation-v1` is added to the validator's global
reserved-role record. No batch, seed, case or reference is created for that
role. The future operator-held confirmation design remains `HUMAN_INPUT`.

## Rationale

This is the smallest operational adapter that satisfies Interface v1 without
inventing a private population or spending compute. The repository already
pins the public PRACTICE bytes and the OpenFOAM-derived records they contain,
so exact-record ingestion can establish provenance without accepting arbitrary
plausible callbacks. Calling the result public adaptive DEVELOPMENT evidence
prevents it from being mistaken for confirmation or qualification.

## Consequences

- The neutral validator can score Cooling submissions end to end on public
  development evidence.
- A changed reference record, contract, rule implementation or public material
  changes a pinned identity or is refused.
- The adapter does not make Graphite confirmation possible by itself.
- Private/official evaluation and service deployment remain separate tickets
  and owner gates.
