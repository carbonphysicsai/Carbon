# ONBOARDING-METRICS-BASIS-01

Ticket ONBOARDING-METRICS-01, owner priority: each Challenge onboarding faster
than the last. Engineering choice: measure artifact-delivery preparation,
NOT fabricate accepted stage or effort durations from commit timestamps.
KEEP existing artifact history and stage map. Public explicit file paths
plus pinned main and pending PR heads bind the sample. Git author identity
is retained but elapsed comparisons use committer UTC; GitHub createdAt and
mergedAt report PR lifetime separately. Shared infrastructure predating a
brief is reuse, not negative work. Concurrent/bundled milestones stay visible.

Report edit span, initial publication lag, successive artifact arrival gaps,
right-censored pending milestones, and unique non-merge commits/author
identities/PRs as proxies. Same Git identity may be many sessions; cannot
infer team headcount. No duration telemetry exists for most historical work:
person-hours and causal blocked time remain null. Future closed effort logs
may contribute explicit self-reported measured durations with provenance;
never convert automation wall time to labour saved.

Reject oldest arbitrary timestamps, summed parallel elapsed stages, shared
PR double-counted as team effort, draft/spec treated as solved/accepted,
and unqualified "each faster" claims. Three recurring bottlenecks are ranked
from observed cohort arrival gaps, with sample counts and bias/censoring,
not claims that their owners are slow. Concrete next automation is proposed,
not new scientific or spend authority. Reversible via metrics sources and
renderer; historical snapshots remain versioned. No reserved value selected.
