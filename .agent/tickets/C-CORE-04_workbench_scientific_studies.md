not establish numerical validity of customer design prose.

The study request and response are closed v1 contracts. Each request carries
one stable operation ID, exact draft binding, physical definition and a
physical-scope digest. Digest numeric values use explicit big-endian binary64

ambiguity. Connect, adoption and display-only edits do not dispatch studies;
start/status/cancel/result reuse the same operation. Parallel transmissions
cannot multiply its allowance. Unknown remaining budgets stay null.

Results retain method/environment identities, resource observations,
refinement evidence, requested output arrays and limitations as data. The
browser never evaluates solver text or renders it as executable markup.
Incomplete task results are not candidate failures or successful science.
Cancellation remains requested until the existing controller observes its
dispatched work and cleanup.

## Evidence and draft lifecycle

The first slice uses a standalone versioned study bundle explicitly bound to
an existing v0.8 draft rather than broadening the established workspace schema.
The UI saves/reopens that bundle within the existing design view. Imports are
unverified until reread through the private service. Conflicting response
bytes reject; changing study inputs requires a new design revision rather
than silently replacing the retained study.

Changes to physical scope invalidate the current association, while editorial
and display changes do not rerun the task. Late responses retain their origin
but cannot attach to a changed draft. Historical fixture, assessment, accepted
reference and campaign identities remain unchanged. No automatic public
training-data handoff exists.

The standalone build keeps `connect-src 'none'`. A separate private-service
build permits same-origin requests to fixed scientific-service routes, requires
an explicit output directory, and embeds neither credentials nor Julia. Host
authentication, draft registration and grants are supplied by the private
operator service; a deterministic local fixture is not production security
acceptance or deployment authority.
