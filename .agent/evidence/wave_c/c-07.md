## Implemented flow

An already-admitted C-01 attempt is claimed once. C-07 first records the exact
frozen generator/case manifest, then accepts the frozen three-replica plan and
three source-owned reconstruction receipts, followed by exact
prediction, supported reference and unresolved measurement result types. Each
identity is appended to C-01's journal in order. The score stage records
`UNRESOLVED_NO_QUALIFIED_SCORE`; it does not create a score or ScoreInput.

After the evidence closure exists, C-06 signs and atomically appends the
DEVELOPMENT receipt. C-07 records that receipt and one digest-only operational
account through C-01's existing result association. Exact replay creates no new
stage, receipt, attempt, replica or result effect. Restart requires explicit
same-claim reconciliation, and interruption between receipt append and result
association converges on the same bytes.

Every non-complete terminal creates a retained operational account with the
source disposition and missing stages. It has no completion receipt. Public and
reviewer projections are distinct allow-lists; private report export contains
digest-only evidence and signature bytes, never TRAIN arrays, protected cases,
answers, seeds or signing-key bytes.

## Candidate verification

Focused CPU tests pass for complete/replay/reopen, explicit reconciliation,
every typed terminal, interrupted association recovery, cross-binding, order,
changed evidence, report idempotency and authority-upgrade denial. The Docker
service test and owner command are implemented and collected locally; exact
Linux service-backed acceptance remains pending.

The service smoke uses one public synthetic Burgers case, the frozen three-
replica lab profile, target-free inference and distinct isolated reference and
measurement workers under the unchanged C-03 profile. It is not the twelve-case
scientific campaign, a Foundax comparison, a repeat-sufficiency finding, an
independent security review, or protected/official/archive/network evidence.
