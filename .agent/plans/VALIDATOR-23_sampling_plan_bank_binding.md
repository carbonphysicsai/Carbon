# VALIDATOR-23 — prospective bank tranche SamplingPlan binding

Status: bounded DEVELOPMENT working contract (2026-10-18). This is an extension of the existing bank ticket under OWNER-EVALUATION-FOCUS-AND-DATA-CYCLE-01, not a scientific qualification or active rule change.

The existing `BankLedger` seals and publishes case provenance, but a tranche does not identify the frozen `SamplingPlan` that governed its draw. The source-owned prospective path will accept an exact authored `SamplingPlanRef` and an explicit effective future slot before drawing a new tranche. The ledger passes that ref to an opt-in source method, stores the ref and slot with the tranche, and refuses a slot that is already drawn. A planned tranche cannot supply a window earlier than its effective slot. Legacy calls retain their journal entries, commitments, signed training files, and draw behavior.

The plan ref's challenge must equal the ledger challenge. Its content digest binds the authored plan's P/Q/w, provenance, version and policy fields; this ledger records that identity but does not establish scientific adequacy or source conformance. A trusted source must implement the planned draw method and receives the effective slot so it can check producer-scheduled commitments outside the ledger. The ledger itself checks already drawn windows; this slice does not claim to validate external schedules. Internal tranche/release provenance can recover the exact ref and effective slot. Public commitments and TRAIN v1 files remain on their existing allow-listed shapes; no private plan contents, seed, rationale, or protected case identity is emitted early.

This slice does not set a new count, cadence, score law, population, retirement policy, winner, LIVE state or publication rule. Existing active windows and tranches are immutable. Cross-plan score comparability remains governed by registered scoring policy, not by this ledger. Design-ledger/cross-bank disclosure dependencies, unresolved comparisons, and successor immutable TRAIN manifests remain separate follow-ups. Focused tests cover legacy byte stability, future-slot refusal, plan identity persistence, and release provenance; canonical Linux acceptance is required because native Windows bank owner-permission tests fail at baseline.
